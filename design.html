Идея — 6 независимых слоёв

Оформление собирается из 6 независимых слоёв. Все 6 — свои на каждом экране.
  1. Стиль — 8 штук.
  2. Палитра + оттенок — 9 палитр × 5 оттенков = 45 комбинаций.
  3. Тень карточек — 8 вариантов.
  4. Тень плавающих кнопок — 8 вариантов.
  5. Тема — светлая / тёмная.
  6. Фон — 19 базовых + свои.

Контраст плашек — по оттенкам

  • Нежная, Светлая, Яркая → --plate-text: var(--c4), --plate-bg: var(--c2).
  • Насыщенная, Глубокая → --plate-text: #fff, --plate-bg: mix(c3 15%, c2 85%).
  • Тёмная тема → --plate-bg: mix(c1 15%, c4 85%), --plate-text: var(--c1).

Все три правила распространены и на .dm-scope.

Светлая / тёмная тема

Хранится в data-theme="dark" на body. Меняет цвета фона, шапки, карточек, чатов, кнопок, нижней навигации, форм, больших модалок.

Фоны — 19 картинок

В папке images/ — 19 картинок (01–05, 07–20; файл 06 отсутствует).

Как работает на сайте.
  1. Двухслойный фон: bg-blur + bg-sharp.
  2. Размытие — через <img>, не через background-image (iOS Safari).
  3. Картинка вписана целиком (object-fit: contain).
  4. Мягкие растворы краёв — mask-image.
  5. Позиция и зум — переменные --tx / --ty / --tz.
  6. Редактор позиции — модалка. Открывается поверх панели, панель не закрывается.

Три слота — по устройству

  • Нет тача → pc. Тач + ширина < 600 → iphone. Тач + ≥ 600 → ipad.
  • Хранилище: bgSettings[bgId] = { iphone:{x,y,z}, ipad:{x,y,z}, pc:{x,y,z} }.
Фон сайта темнее карточки.
Карточка — var(--c1). Фон сайта — color-mix(in srgb, var(--c1) 65%, var(--c2) 35%).

Структура (классы)

  • .design-panel-box — коробка панели.
  • .design-panel-head — шапка: заголовок + тумблер + крестик.
  • .design-panel-columns — контейнер двух колонок.
  • .design-panel-body — левая колонка с настройками.
  • .design-panel-mockup dm-scope — правая колонка с макетом.
  • .design-panel-footer — нижняя полоска: кнопки.
  • .dp-action — общий класс кнопок. .dp-action-apply — «Применить», .dp-action-preview — «Посмотреть».
Все секции сворачиваются. Состояние помнится (ключ designSectionsCollapsed).

Размеры панели и макета

  • Панель: max-width: 900px. Высота по содержимому, но не больше 96vh.
  • Макет: width: 400px. Пропорции как у окна браузера — aspect-ratio из window.innerWidth / window.innerHeight через syncMockupAspect().
  • На ПК макет широкий и низкий, на iPad высокий. Не растянут на всю высоту панели — компактно сверху правой колонки.
  • Все элементы макета ужаты под низкое окно ПК.
  • Нижняя полоска макета прижата к низу коробочки (margin-top:auto).
Почему макет — не «на всю высоту панели». Макет показывает, как реально ляжет фон. Фон ляжет по пропорциям окна браузера. Если макет растянуть — фон обрежется «слишком удачно» и не совпадёт с реальностью.

Классы внутри макета (префикс dm-)

  • .design-panel-mockup — обёртка. У неё же класс .dm-scope. На ней data-style, data-palette, data-shadow, data-theme.
  • .dm-bg — картинка фона внутри макета. Лежит на дне. Класс dm-bg-on — показана.
  • .dm-header — полоска шапки. .dm-logo — кружок слева. .dm-icons span — три точки справа.
  • .dm-contents — полоска содержания. .dm-chip — чипы (3 штуки).
  • .dm-card — прямоугольник карточки. .dm-photo — фото сверху. .dm-card-body — тело.
  • .dm-title — «Название» курсивом (текст через ::before).
  • .dm-tags / .dm-tag — плашки тегов.
  • .dm-kcal span — чёрточки КБЖУ.
  • .dm-buttons / .dm-btn / .dm-btn-primary — две кнопки.
  • .dm-nav span — полоска нижней панели с четырьмя точками.

Всё в app/css/style.css, в конце файла.

Черновик и предпросмотр

Черновик designDraft — в памяти, не в localStorage. Живёт, пока панель открыта. Обнуляется при закрытии.

Как работает

  1. Открытие панели: designDraft = { ...сохранёнка текущего экрана }.
  2. Клик по стилю / палитре / оттенку / тени / теме / фону — меняет поле в designDraft. Не трогает страницу. Обновляет макет и подсветку чипов.
  3. Крестик / клик по фону / Escape — designDraft = null. Панель закрывается.

Кнопка «Применить»

  1. Клик → открывается окошко «Применить к…» (см. ниже).
  2. Пользователь отмечает галочками, к каким экранам применить.
  3. Клик по «Применить» в окошке:
    • Черновик копируется в отмеченные экраны (setDesignFor).
    • Окошко закрывается.
    • Панель закрывается, designDraft = null.
    • applyDesignFor(activeDesignScreen) — применяет к body.
    • Фон применяется через applyBg().

Окошко «Применить к…»

Применить к:
[ ] 🏠 Главная
[ ] ❤ Избранное
[ ] 📅 План
[ ] 🧺 Кладовая
[Отмена]  [Применить]
  • Все галочки пустые. Пользователь сам отмечает.
  • «Применить» неактивна, пока не отмечен хотя бы один экран.
  • «Отмена» — закрывает окошко, черновик остаётся. Если был открыт предпросмотр — возвращает в панель.

Классы: .apply-to-list, .apply-to-row, .apply-to-check, .apply-to-actions, .apply-to-btn.

Режим предпросмотра (телефон)

Проблема. На телефоне (ширина < 800) макета нет. Клики в панели визуально ничего не показывают. Панель «слепая».

Решение — кнопка «Посмотреть».

  • Ширина < 800 — видны обе кнопки: «Посмотреть» и «Применить».
  • Ширина ≥ 800 — только «Применить». Макет справа, предпросмотр не нужен.

Как работает предпросмотр

  1. Пользователь накликал в панели. Жмёт «Посмотреть».
  2. Панель скрывается.
  3. Страница показывает черновик — стиль, палитру, тени, тему, фон.
  4. Внизу по центру — плашка предпросмотра: [Применить] [Вернуться].
  5. «Вернуться» — плашка прячется, панель возвращается, страница откатывается к сохранёнке. Черновик цел.
  6. «Применить» — открывается «Применить к…».

Классы: #previewBar / .preview-bar, .preview-btn. Функции: enterPreview(), exitPreview(), applyDraftToBody(). Флаг isPreviewing.

Переключение экранов при открытой панели

Логика блокировки работает. Панель перекрывает весь экран тёмным фоном, нижняя навигация недоступна. Уйти на другой экран — только закрыв панель.
В режиме предпросмотра (телефон) — навигация доступна. Панель скрыта, страница показана как обычно. Пользователь может уйти на другой экран прямо в предпросмотре. Черновик при этом не теряется — он в памяти, вернётся при «Вернуться» или «Применить».
Смена оформления при переключении экранов — мгновенная, без анимации.

Кнопки, которые НЕ делаем

Отдельная кнопка «Отмена» в панели. Крестик = отмена = выброс черновика. Отдельной кнопки не нужно.
Отдельная кнопка «Сбросить». Сброс = выбрать другой стиль. Если понадобится — добавим.

Редактор позиции фона

  • Кнопка «📐 Позиция» в панели → открывается редактор поверх панели. Панель не закрывается.
  • Редактор берёт фон из черновика (designDraft.bg), а не с сайта.
  • Позиция и зум сохраняются в bgSettings[bgId][device].

.bg-editor — z-index: 100003. Переменная bgEditorBg — фон, для которого открыт редактор.

Почему редактор поверх панели. Раньше кнопка закрывала панель — и черновик терялся. Теперь панель живёт, пока пользователь настраивает позицию.

Идея. У каждого из четырёх экранов (🏠 ❤ 📅 🧺) — своё оформление. Меняешь стиль на Главной — на Избранном он остаётся прежним.

Функции в design.js

  • loadDesignData() — загружает структуру.
  • getDesignFor(screen) — сохранёнка.
  • getActiveDesign() — черновик или сохранёнка.
  • setDesignFor(screen, patch) — сохранить.
  • applyDesignFor(screen) — применить к body.
  • syncMockupScope() — применить черновик к макету (включая фон).
  • syncMockupAspect() — пересчитать пропорции макета.
  • applyDraftToBody() — применить черновик к body без сохранения.
  • enterPreview() / exitPreview() — режим предпросмотра.
  • openApplyTo() / closeApplyTo() — окошко «Применить к…».

Правила и уроки дизайна

Переменные на body не наследуются в .dm-scope автоматически.
Если CSS-переменная объявлена как body{--что-то:...}, на .dm-scope она приходит уже посчитанной. Если внутри макета переменная должна пересчитываться — её надо переопределить на .dm-scope отдельно.
Пример: --plate-bg / --plate-text в card.css висели на body, и макет брал их оттуда — старыми. Пришлось продублировать на .dm-scope.
Хвост подшага 7 — «Общая / Своя» позиция фона.
Идея. Позиция и зум фона по умолчанию общие для картинки на всех экранах. Можно «отвязать» для конкретного. Переключатель в редакторе: (●) Общая / ( ) Своя для этого экрана. Точка-звёздочка на квадратике с картинкой в панели.
Почему отложено. Требует переработки bgSettings — сейчас он не привязан к экранам, только к устройствам.
Смена устройства и корзина. Что происходит с ингредиентами и корзиной при смене устройства готовки. Обсудим, когда будем делать экран «Устройство готовки».
