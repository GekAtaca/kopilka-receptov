2 · Кто пользователь

Личный проект для себя. Не для клиента, не для портфолио.

Главное

  • Не программист. Работает в VS Code и GitHub Desktop, код копирует.
  • Windows 11. Техника: iPhone 13, iPhone 16 Pro Max, iPad Air 11 (M2), ПК.
  • Внимательна к деталям. Заметит нечитаемый текст, кривую линию, лишние полосы, нестыковки превью и сайта.
  • Устаёт от длинных инструкций. Один шаг за раз: сделала → сохранила → обновила → показала → следующий.
  • Лучше понимает визуально. Скриншоты работают. Скрины со стрелочками работают лучше всего.
  • Есть вкус. Отклоняет то, что не подходит, объясняет почему.
  • Честная. Скажет прямо: «не нравится», «убери», «ты торопишься», «ты меня запутал», «не помню».
  • Разбирается в DevTools. Спокойно открывает Console, вводит команды, присылает результат. Открывает Network, ставит Disable cache.

3 · Как работать с ИИ

Главные правила (не нарушать)

Перед отправкой кода — свериться с этой картой. Не по памяти. Длинный диалог → доверять карте и скринам, а не «кажется, я помню».
Сначала решение — потом код. Пока пользователь не сказал «ок, давай код» — обсуждаем словами. Никакого кода заранее.
Один шаг за раз. Сделала → сохранила → обновила → показала → следующий. Не давать десять правок в одном сообщении.
Код — целым блоком. Не «замени строчку». Либо «найди этот текст → замени на этот текст», либо «удали эти строки», либо «поставь курсор в конце строки X, нажми Enter, вставь это».
Не повторять код, если он уже был дан. Если пользователь его получил — не дублировать, только напомнить, что он выше в переписке.

Как формулировать правки (важно!)

Пользователь жаловалась на формулировки вроде «найди блок .bg-sharp и замени». Это её путает. Правильные формулировки:

Формат 1 — замена по тексту.
«Найди в файле этот код:
.bg-sharp{ position:absolute; ... } Замени его целиком на:
.bg-sharp{ ... }
Формат 2 — замена по номерам строк (когда видно на скрине).
«Замени строки 296–322 на этот блок». Но номера строк видны только на скрине с номерами. Если номера могут «поехать» — не рисковать, использовать Формат 1.
Формат 3 — вставка.
«Поставь курсор в конце строки X. Нажми Enter. На новой строке вставь этот блок».
НЕ говорить «вставь в неё» — непонятно, в какую именно строку.
Формат 4 — удаление.
«Удали эту строку целиком: ...»
«Удали эти строки: от ... до ...».
Если пользователь не находит то, что ИИ просит — не угадывать. Попросить скрин нужного места с номерами строк (в VS Code они в серой колонке слева). По скрину дать точную инструкцию. Не продолжать угадывать вслепую.
Если пользователь говорит «этого нет» — немедленно остановиться и попросить скрин. Не придумывать ещё один вариант правки «на всякий случай». Уже проверено: скрин быстрее любых догадок.

Commit + Push — обязательно перед проверкой на устройстве

У пользователя нет прямого доступа к файлам на iPhone/iPad. Проверить на телефоне или планшете можно только через GitHub Pages — а для этого нужен Commit + Push.
Если пользователь должна посмотреть на iPhone/iPad — в инструкции первым делом: «сохрани, обнови на ПК; если ок — Commit + Push; подожди 1–2 минуты; открой на устройстве».

Как пользователь проверяет (инструменты, которыми она пользуется)

DevTools (F12) в браузере — рабочий инструмент. Пользователь умеет:
  • Открыть Console и ввести команду типа document.body.dataset.theme = 'dark'. И прислать результат.
  • Открыть Network и поставить Disable cache. И приложить скрин списка загрузок со статусами (200 или 304).
  • Открыть Elements, выделить элемент, показать панель Styles.
Практика: если правило есть в файле, но не применяется — проверить через Console. Это быстрее, чем смотреть Styles в узкой панели.

Честность про память

Если диалог длинный и ИИ начинает путаться — сказать прямо: «Я начинаю терять нить». Не делать вид, что помню.

Что пользователь уже знает

VS Code GitHub Desktop Live Server Commit / Push GitHub Pages HTML / CSS Тег, класс DevTools (F12) Console, Network Кэш браузера Ctrl+Z откат

Рекомендации ИИ для следующей сессии (выработаны на практике v5 → v6)

  1. Скрины со стрелками — лучший язык. Если пользователь объясняет словами и ИИ не понимает с первого раза — сразу просить скрин с обведённым проблемным местом. Не пытаться угадывать «ещё разок».
  2. «Не то» без объяснений — нормально. Спрашивать: «что именно не то — цвет, яркость, читаемость, размер, расположение?» Или просить скрин.
  3. При застревании — просить файлы. Формула «пришли index.html, card.css, style.css» работает как reset. Пользователь сделает это охотно.
  4. Проверять закрытие скобок в CSS. Уже дважды (тени vniz, в другом месте) незакрытая } ломала следующие правила. Если добавляется блок selector{...} — напоминать: «после box-shadow:...; должна быть } на своей строке».
  5. DevTools Console — рабочий инструмент. Проверять гипотезы через getComputedStyle(...).backgroundColor, element.matches('selector') — быстро и без правок в файлах.
  6. Скрин Network → Disable cache. При подозрении на кэш — просить сделать это и приложить скрин со статусами загрузки (200 = свежие, 304 = из кэша).
  7. Не забывать про !important. Когда старое правило мешает и не находится — добавлять в конец файла с !important. Пользователь понимает зачем.
  8. Проверять иерархию цветов. В тёмной теме «плашки светлее фона», «badge — акцент». Не делать всё одного цвета. Пользователь это видит и не одобрит.
  9. Не бояться переспрашивать. «Я не понял, что ты имеешь в виду — покажи скрином» — быстрее, чем тыкать вслепую.
  10. У пользователя есть вкус. Когда говорит «не читается» или «не вписывается» — это точное попадание. Доверять.

Как работает. Палитра задаётся атрибутом data-palette="[название]-[оттенок]" на <body>. Задаёт 4 CSS-переменные: --c1, --c2, --c3, --c4.

  • Активная палитра / оттенок подсвечиваются.
  • Оттенок запоминается между сменами палитры.
Хранилище: ключ designPalette в localStorage — {palette, shade}.

Контраст плашек — правила (новое в v6)

В карточке есть плашки: теги, кнопки порций +/−, «Сковорода», «Моя заметка», кнопки внизу. Их фон и текст — через переменные:
  • --plate-bg — фон плашки
  • --plate-text — цвет текста
Логика по оттенкам:
  • Нежная, Светлая, Яркая → --plate-text: var(--c4) (тёмный текст на светлом фоне).
  • Насыщенная, Глубокая → --plate-text: #fff, --plate-bg: mix(c3 15%, c2 85%) (светлый текст на чуть затемнённом фоне).
Правило: пользователь отказалась от идеи «плашки = тёмный фон c4 как badge». Плашки остаются мягкими — чуть темнее тела карточки на тёмных оттенках.
Правило: без неона. Цвета приглушённые, спокойные, «вечерние».

Что НЕ работает автоматически: если появляется новый элемент, использующий --c4 как цвет текста — на тёмной теме он станет невидимым. Правило: при добавлении нового элемента с текстом проверять, что для тёмной темы есть явное правило (обычно через body[data-theme="dark"] .selector{color:#fff}).
Зафиксировано: инверсия **простая** (c1↔c4 для фона/текста, c3 как акцент для badge). Не 100%-я инверсия — акценты и рамки остаются в палитре.

5.6. Фоны ✅ финализированы в v5

В папке images/ — 19 картинок (01–05, 07–20; файл 06 отсутствует).

Как работает (итоговое решение).
  1. Двухслойный фон: bg-blur (та же картинка, размытая, filter:blur(40px)) + bg-sharp (чёткая). Оба — в обёртке .bg-sharp-wrap.
  2. Размытие НЕ через background-image (в этом проекте Safari не отрисовывает background-image на iOS) — только через <img>.
  3. Картинка вписана целиком (object-fit:contain), а не обрезана. По краям видно размытие.
  4. Мягкие растворы краёв — через mask-image: radial-gradient(...) на .bg-sharp.
  5. Позиция и зум — через CSS-переменные --tx / --ty / --tz.
  6. Редактор позиции — модалка, открывается из панели 🎨 (кнопка «📐 Позиция»).

Редактор позиции — как работает

  • Пропорции превью = пропорции текущего окна браузера. Что видишь — то и на сайте. Превью честное.
  • Таскаешь картинку — мышью на ПК, пальцем на телефоне.
  • Зум — колесо мыши на ПК, щипок двумя пальцами на телефоне. Двойной клик — сброс на 1×.
  • Диапазон: от 1× (вписана) до 5× (крупный фрагмент).

Три слота — по устройству

Отдельная настройка для каждого из трёх устройств.
  • Определение — автоматически: нет тача → pc; тач + ширина < 600px → iphone; тач + ширина ≥ 600px → ipad.
  • Хранилище: bgSettings[bgId] = { iphone:{x,y,z}, ipad:{x,y,z}, pc:{x,y,z} }.

Правило выбора фона vs палитры

На iPhone тяжёлый фон может подтупливать — это ограничение iOS Safari. Если тормозит — можно отказаться от фона и выбрать красивую палитру. Палитра лёгкая и работает мгновенно.

⚡ Важно: оформление — локальное, НЕ синхронизируется

Синхронизируются только данные — рецепты, план, покупки, кладовая.

Оформление — локальное у каждого:

  • Стиль — у каждого свой.
  • Палитра + оттенок — у каждого своя.
  • Тень — у каждого своя. новое в v6
  • Тема (светлая/тёмная) — у каждого своя. новое в v6
  • Фон — у каждого свой (или без фона).
  • Позиция фона — у каждого своя.

Пользователь подтвердила: синхронизировать оформление не нужно. Когда появится синхронизация — она коснётся данных, не оформления.

18 · Известные баги браузеров

18.1. iOS Safari: position:fixed + z-index:-1

Симптом. Фоновый слой с position:fixed; z-index:-1 на iPhone/iPad: при скролле фон уезжает вверх или перекрывает контент.
Решение (работает).
  1. Фон — position:fixed; z-index:0.
  2. Контент в обёртке <div class="app"> с position:relative; z-index:1.
  3. На .bg-layer — transform: translateZ(0) и will-change: transform.

18.2. iOS Safari: полоса внизу экрана

Симптом. Внизу остаётся светлая полоса между картинкой и панелью Safari.
Решение — оставили как есть. Полоса мелкая, сливается со светлой палитрой. В Chrome на iPhone — полосы нет.

18.3. iOS/iPadOS Safari: агрессивный кэш CSS/JS

Решение: открыть сайт в приватном окне. Или DevTools → Network → Disable cache → Ctrl+F5.

18.4. iOS Safari: background-image не отрисовывается

Симптом. Фон через background-image: url(...) на <body> или <html> не рисуется.
Решение: только <img> с position:fixed.

18.5. iOS Safari: mask-composite + blur + scale крашит рендер

Симптом. Комбинация filter:blur(40px) + mask-composite: intersect + transform:scale — Safari крашит страницу.
Решение:
  • Маска на картинке, не на обёртке.
  • Один радиальный градиент вместо двух линейных с mask-composite.
  • Никаких mask-composite на iOS.
  • Раздельные свойства (не сокращённое mask).

18.6. Незакрытая } в CSS ломает следующие правила новое в v6

Симптом. Правило есть в файле, но не применяется. Или следующее правило «прилипает» внутрь предыдущего и работает только при определённых условиях.
Что было: в card.css в блоке body[data-shadow="vniz"] .card{...} пропала закрывающая } — и все правила тёмной темы оказались вложены в это правило. Тёмная тема не работала, пока data-shadow="vniz" не выставлен.
Правило для профилактики:
  • После вставки нового блока selector{...} — проверять, что } на месте.
  • В VS Code навести курсор на { — подсветится парная }. Если подсветка ушла далеко вниз — значит где-то не хватает } выше.
