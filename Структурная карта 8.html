2 · Кто пользователь

Личный проект для себя. Не для клиента, не для портфолио.

Главное

  • Не программист. Работает в VS Code и GitHub Desktop, код копирует.
  • Windows 11. Техника: iPhone 13, iPhone 16 Pro Max, iPad Air 11 (M2), ПК.
  • Внимательна к деталям. Заметит нечитаемый текст, кривую линию, лишние полосы, нестыковки превью и сайта.
  • Устаёт от длинных инструкций. Один шаг за раз: сделала → сохранила → обновила → показала → следующий.
  • Лучше понимает визуально. Скриншоты работают. Скрины со стрелочками работают лучше всего. Схемы с отступами (типа дерева) — НЕ понимает. Объяснять словами.
  • Есть вкус. Отклоняет то, что не подходит, объясняет почему.
  • Честная. Скажет прямо: «не нравится», «убери», «ты торопишься», «ты меня запутал», «не помню».
  • Разбирается в DevTools. Спокойно открывает Console, вводит команды, присылает результат. Открывает Network, ставит Disable cache.
  • Не разбирается в коде. Говорит прямо: «в кодах я не разбираюсь». Значит, инструкции должны быть максимально пошаговые, без номеров строк (они «поехали»), только «найди этот текст → замени на этот» или «поставь курсор в конце строки X → Enter → вставь».
  • Хочет вместе решать дизайн. Не «вот код, делай». Обсуждать, задавать вопросы, спорить. Если ИИ упустил что-то — она заметит и скажет.

3 · Как работать с ИИ

Главные правила (не нарушать)

Перед отправкой кода — свериться с этой картой. Не по памяти. Длинный диалог → доверять карте и скринам, а не «кажется, я помню».
Сначала решение — потом код. Пока пользователь не сказал «ок, давай код» — обсуждаем словами. Никакого кода заранее.
Обсуждаем одну фичу (или один подшаг) — до конца. Потом сразу код. Не растягивать обсуждение на всё сразу. Не обсуждать все подшаги, а потом садиться кодить. Каждый подшаг: обсудили → сделали → проверили → следующий. Обсуждение — не бесконечное.
Один шаг за раз. Сделала → сохранила → обновила → показала → следующий. Не давать десять правок в одном сообщении.
Код — целым блоком. Не «замени строчку». Либо «найди этот текст → замени на этот текст», либо «удали эти строки», либо «поставь курсор в конце строки X, нажми Enter, вставь это».
Никаких номеров строк. Пользователь сказала: «без строк они все равно меняются, так только запутаешь». Только поиск по тексту.
Не повторять код, если он уже был дан. Если пользователь его получил — не дублировать, только напомнить, что он выше в переписке.

Как формулировать правки (важно!)

Формат 1 — замена по тексту. «Найди в файле этот код: [блок]. Замени его целиком на: [блок]».
Формат 2 — вставка. «Поставь курсор в конце строки X. Нажми Enter. На новой строке вставь этот блок».
Формат 3 — удаление. «Удали эту строку целиком». «Удали эти строки: от … до …».
Если пользователь не находит то, что ИИ просит — не угадывать. Попросить скрин нужного места. По скрину дать точную инструкцию. Не продолжать угадывать вслепую.
Если пользователь говорит «этого нет» — немедленно остановиться и попросить скрин. Не придумывать ещё один вариант правки «на всякий случай».
Не давать код сразу, если не согласовано решение. Сначала решение — потом код.
Сомневаешься — спроси. Не гадай. Общее правило на любую ситуацию, не только про поиск в коде. Не уверен, что понял — переспроси. Не уверен, что правильно — уточни. Не выдумывай.
При застревании — просить файлы. «Пришли index.html, card.css, style.css» работает как reset. Если диалог длинный и стало тяжело — попросить файлы, чтобы свериться с реальным состоянием.
Не забывать про !important. Когда старое правило мешает и не находится — добавлять в конец файла с !important. Это рабочий приём, не костыль.
ИИ не может отправлять скрины. Только пользователь. ИИ может попросить: «покажи это место скрином». Даёт инструкции словами.
Схемы с отступами («деревом», с символами ├── и └──) пользователь НЕ понимает. Объяснять словами, таблицами, или плоским списком.
Сначала обсуждать дизайн полностью — потом писать код. Пользователь любит, когда решение продумано целиком до кода, с ответами на все вопросы. Если ИИ начинает кодить раньше — она остановит и попросит обсудить.

Commit + Push — обязательно перед проверкой на устройстве

У пользователя нет прямого доступа к файлам на iPhone/iPad. Проверить можно только через GitHub Pages — для этого нужен Commit + Push.
Если пользователь должна посмотреть на iPhone/iPad — в инструкции первым делом: «сохрани, обнови на ПК; если ок — Commit + Push; подожди 1–2 минуты; открой на устройстве».

Как пользователь проверяет

DevTools (F12) в браузере — рабочий инструмент. Умеет:
  • Открыть Console, ввести команду, прислать результат.
  • Открыть Network, поставить Disable cache.
  • Открыть Elements, выделить элемент, показать Styles.

Честность про память

Если диалог длинный и ИИ начинает путаться — сказать прямо: «Я начинаю терять нить». Не делать вид, что помню.
Если пользователь предлагает обновить карту до конца сессии — соглашаться. Длинный диалог → карта как страховка. Пользователь сама это предложила.
Если карта противоречит реальному коду — доверять коду. Код — это реальное состояние проекта, карта — описание. Если обнаружилось расхождение — поправить карту под код, а не наоборот. Исключение — если пользователь явно говорит «в коде ошибка, надо исправить по карте».

3.2. Что работает / что не работает в объяснениях

Работает:
  • «Найди этот текст → замени на этот».
  • «Поставь курсор в конце строки X → Enter → вставь это».
  • «Удали эти строки целиком».
  • Скрины от пользователя — со стрелочками, с выделением, с номерами строк.
Не работает:
  • Схемы «деревом» с отступами (символы ├──, └──). Пользователь их не понимает.
  • Номера строк в инструкциях. Они всё равно «поедут». Только поиск по тексту.
  • ИИ не может отправлять скрины. Только просить у пользователя.
  • Ссылаться на «мы же помним». Если диалог длинный — доверять карте, а не памяти.

3.3. Как войти в курс дела (для нового ИИ)

Порядок: прочитать карту → сказать своими словами, что понял → спросить, что уточнить → и только потом работать. Не бросаться с кодом. Не переспрашивать то, что уже решено.

3.4. Отдельные правила поведения

Если пользователь устала — остановиться. Короткие неопределённые ответы («вроде ок», «норм», «не помню») — это не значит «всё точно работает». Спросить конкретнее: «проверь вот эти три штуки — всё на месте?». Или предложить паузу. Если есть сомнения в её согласии — предложить варианты решения, чтобы она выбрала.
Если пользователь говорит «не то» без объяснений — предложить 2–3 варианта. Не мучить вопросом «что именно не то?». Предложить: «может, цвет? может, отступ? может, размер? может, расположение?». Она покажет пальцем. Не настаивать — если хочет сказать сама, скажет.
Пометка для следующего ИИ: сообщить пользователю после следующей сессии — помог ли этот приём или лучше убрать из карты.
Не переспрашивать то, что уже решено. Если правило есть в карте — не задавать по нему вопрос заново. НО: если пользователь сама вернулась к вопросу («а может, всё-таки…», «а что если…») — значит, передумала. Обсуждаем заново, не ссылаемся на «мы же решили».

  • --plate-text — цвет текста

  • Насыщенная, Глубокая → --plate-text: #fff, --plate-bg: mix(c3 15%, c2 85%).
Плашки в содержании на тёмной теме — наведение. При наведении плашка светлеет: фон var(--c2), текст var(--c4).

19 · Известные баги браузеров

19.1. iOS Safari: position:fixed + z-index:-1

Симптом. Фон с position:fixed; z-index:-1 на iPhone/iPad: при скролле фон уезжает.
Решение. Фон — position:fixed; z-index:0, контент в .app с z-index:1. На .bg-layer — translateZ(0) и will-change:transform.

19.2. iOS Safari: полоса внизу экрана

Симптом. Внизу полоса между картинкой и панелью Safari. Решение — оставили как есть.

19.3. iOS/iPadOS Safari: агрессивный кэш CSS/JS

Решение: приватное окно. Или DevTools → Network → Disable cache → Ctrl+F5.

19.4. iOS Safari: background-image не отрисовывается

Симптом. Фон через background-image на <body> или <html> не рисуется.
Решение: только <img> с position:fixed.

19.5. iOS Safari: mask-composite + blur + scale крашит рендер

Симптом. Комбинация filter:blur(40px) + mask-composite: intersect + transform:scale — Safari крашит страницу.
Решение: маска на картинке, не на обёртке; один радиальный градиент вместо двух линейных; никаких mask-composite на iOS.

19.6. Незакрытая } в CSS ломает следующие правила

Симптом. Правило есть, но не применяется. Уже трижды случалось.
Правило для профилактики: после вставки блока — проверить, что } на месте. В VS Code навести на { — подсветится парная.

19.7. iOS Safari: анимация position:fixed за границей экрана

Симптом. Плавающие кнопки при исчезновении — анимировались мгновенно. Safari «оптимизирует» анимации того, что вне экрана.
Решение: сдвиг уменьшен с 300px до 50px + opacity: 0 + visibility:hidden с задержкой .4s. Анимация 400ms.

19.8. iOS Safari: событие scroll не срабатывает во время инерционной прокрутки

Симптом. Пока палец двигает страницу — событие scroll молчит.
Решение: использовать touchend вместо scroll для запуска таймера скрытия. Плюс touches.length === 0.

19.9. Скрипт выполняется раньше HTML

Симптом. Скрипт в <head> или до элементов DOM — не находит элементы.
Решение. Обернуть в document.addEventListener('DOMContentLoaded', function(){...}).
