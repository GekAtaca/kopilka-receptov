Продукты

База продуктов. Формат, группы, единицы измерения. Пикер. Форма. Дубликаты. Редактирование.

Что такое база продуктов

Всё, что можно положить в рецепт — это продукт. Молоко, мука, яйца, помидоры, куриное филе. У каждого продукта есть КБЖУ на 100 г, единица измерения, группа.

База продуктов состоит из двух частей:

1. Готовая база — файл products-base.js в коде. 309 продуктов в 19 группах. КБЖУ из официальных российских справочников. Править напрямую нельзя — но можно скопировать продукт в свою базу и там править.
2. Своя база — то, что пользователь добавила сама (свои марки, домашние блюда). Хранится в IndexedDB, таблица products. Создавать, править, удалять.
При поиске обе базы объединяются в один список. Сначала — свои (⭐), потом — готовые. Внутри — группировка по типу (🥛 Молочные, 🥩 Мясо и птица и т.д.).

Про галочку «КБЖУ на 100 мл»

Зачем она. На упаковке молока пишут КБЖУ на 100 мл, а не на 100 г. Но в базе всегда хранится на 100 г — это правило. Галочка говорит системе: «числа в полях — на 100 мл, пересчитай на 100 г через плотность».

Пример. Молоко, на упаковке: 60 ккал · Б3 · Ж3.2 · У4.7 на 100 мл. Плотность 1.03.

Что сохраняется в базе:

  • kcal: 58.3 (60 ÷ 1.03, округлено до 1 знака)
  • protein: 2.9, fat: 3.1, carbs: 4.6
  • density: 1.03, unit: 'мл'
  • kbzhuOn100ml: true
  • kbzhuMl: { kcal: 60, protein: 3, fat: 3.2, carbs: 4.7 } — исходные, как на упаковке
Зачем хранить оба набора. Когда пользователь откроет продукт на редактирование — в полях КБЖУ покажутся исходные числа (kbzhuMl), как на упаковке. Пользователь всегда работает с упаковкой, а не с пересчитанными числами.

Правила работы с базами

КБЖУ у продукта всегда хранится на 100 г. Если на упаковке указано на 100 мл или на порцию — сайт пересчитывает через плотность. Это правило — база для всех расчётов рецепта.
В рецепте — короткое имя ингредиента. Полное имя (с маркой) хранится в базе, в рецепте показывается shortName. КБЖУ берётся из твоей версии продукта, если она есть.
Готовая база — можно копировать в свою и править. Напрямую править нельзя.
Своя база — создавать, править, удалять.
Переопределение. Открыть продукт из готовой базы → «Переопределить для себя». Создаётся своя версия (⭐). При поиске она первая. В рецептах, где использован готовый продукт, автоматически используется своя версия. Пока не реализовано — отложено.
Удаление продукта. Спрашиваем «Используется в N рецептах. Удалить?». Не запрещаем.
Удалённое переопределение → ингредиенты возвращаются к готовому продукту. Без ⚠.
Удалённый уникальный продукт → ингредиенты получают ⚠, КБЖУ не считается.
При редактировании продукта — если используется в рецептах, КБЖУ пересчитывается автоматически во всех рецептах. Без вопроса.

Ложки и стаканы

1 ч.л. = 5 мл · 1 ст.л. = 15 мл · 1 стакан = 200 мл · щепотка = 1 г · горсть = 30 г.

Пересчёт между единицами

  • Жидкости — через плотность (молоко 1.03, масло 0.92, мёд 1.42).
  • Сыпучие (мука, сахар, соль, крупа) — через фиксированные таблицы (1 ст.л. муки = 25 г, 1 ст.л. сахара = 25 г, 1 ч.л. соли = 10 г).
  • Штучные — через вес 1 шт.
Яйца — одна запись на категорию. «Яйцо C0» (70 г), «C1» (60 г), «C2» (50 г), «C3» (40 г). Категория выбирается в рецепте.

Уточнение веса для штучных ⏳ планируется

В рецепте можно писать двумя способами:
  • Суммарный вес: «Помидоры — 790 г». Точно.
  • По штукам: «Помидоры — 3 шт». Система берёт средний вес (200 г × 3 = 600 г). Быстро.
Кнопка ⚖ «Уточнить вес» — позволит взвесить каждую штуку отдельно. Ещё не сделана.

Что умеет пикер

Поиск

  • Строка сверху. Фильтрует по названию и короткому названию.
  • Крестик очистки внутри поля — появляется, когда есть текст.
  • При активном поиске все группы раскрываются автоматически — чтобы видеть результаты. Свёрнутость не сбрасывается: очистила поиск — вернулось как было.
  • При активном поиске клик по заголовку группы ничего не делает — поиск и так всё раскрывает.

Группировка

  • Сверху — «⭐ Мои продукты», всегда. Даже если пусто — с подписью «Пока пусто».
  • Внутри «Моих» — подгруппы по 19 группам. Пустые подгруппы не показываются.
  • Ниже — базовые группы. Пустые базовые группы не показываются.
  • При активном поиске группы раскрываются (см. выше).

Свёрнутость

  • Клик по заголовку группы — свернуть / развернуть.
  • Состояние помнится между открытиями пикера — в IndexedDB, ключ productPickerCollapsed.
  • По умолчанию базовые группы свёрнуты, «Мои» развёрнуты.

Кнопка ⇕ — «развернуть / свернуть всё»

  • Справа от поиска, перед кнопкой «+».
  • Двухсостояние: иконка ⇧ когда есть развёрнутые группы (клик → свернуть всё). ⇕ когда всё свёрнуто (клик → развернуть всё).
  • При активном поиске скрыта — смысла нет.

Кнопка + — создать новый продукт

  • Справа от ⇕.
  • Открывает форму продукта поверх пикера. Пикер не закрывается — поиск и свёрнутость сохраняются.

Сортировка «Моих» — кнопка ≡

  • В заголовке «⭐ МОИ ПРОДУКТЫ», рядом с цифрой.
  • Открывает dropdown с 4 вариантами:
    • 🕐 Сначала новые (дефолт)
    • 🕐 Сначала старые
    • 🔤 А → Я
    • 🔤 Я → А
  • Dropdown висит у самой кнопки (position:fixed + расчёт координат). Раскрывается вверх, а если места нет — вниз.
  • Выбор помнится между открытиями — ключ productSort.
  • Сортировка меняет порядок только внутри подгрупп «Моих». Порядок самих подгрупп — по order из PRODUCT_GROUPS (Молочные → Мясо и птица → Рыба...).
  • Кнопка скрыта, если «Мои» пусты.
Сортировка по частоте использования — не сейчас. Идея: сортировать по тому, как часто пользователь берёт продукт в рецепты. Пока не реализовано — в базе всего 9 демо-рецептов, «частота» бессмысленна. Вернёмся, когда рецептов станет много.

Клик по продукту — выбрать

  • Клик по продукту (своему или базовому) → продукт уходит наружу через onSelect. Пикер закрывается.
  • Что делает вызывающий код с этим продуктом — его дело (в рецепте — добавляет как ингредиент).

Правый клик / долгий тап — контекстное меню

  • Только на своих продуктах. На базовых — работает системное меню браузера.
  • ПК: правый клик. Телефон/iPad: долгий тап (0.5 сек).
  • Меню: ✎ Редактировать и 🗑 Удалить (красным).
  • Редактировать — работает. Открывает форму поверх пикера с заполненными полями.
  • Удалить — пока заглушка «Удаление появится позже».
  • Меню закрывается: клик мимо, Escape, скролл списка, ресайз окна.

Поведение после создания — afterCreate

Зачем. Пользователь создаёт продукт из разных мест. Из редактора рецепта — продукт должен сразу попасть в рецепт. Из кладовой — просто лечь в базу.

Параметр afterCreate у пикера. Два значения:

ЗначениеЧто происходит после сохранения
'list' дефолтФорма закрывается, пикер на месте, новый продукт виден в «⭐ Мои продукты». Пользователь сам решает, что с ним делать.
'select'Форма закрывается, пикер закрывается, продукт уходит наружу через onSelect.

Кто задаёт:

  • Редактор рецепта (шаг 37) → 'select'
  • Кладовая (шаг 11 плана) → 'list'
  • Никто не задал (тест из консоли) → 'list'

Форма продукта

Файл app/js/product-form.js. Открывается из пикера (кнопка «+» или контекстное меню «✎ Редактировать»).

Поля

Основные

  • Название — обязательно. Например: «Молоко Простоквашино 3.2%».
  • Короткое название — необязательно. Если пусто — подставляется длинное.
  • Марка — необязательно.
  • Группа — обязательно. Выпадающий список из 19 групп. По умолчанию — пусто (не «Молочные»).

КБЖУ и единицы

  • КБЖУ — 4 поля в ряд (ккал, Б, Ж, У). Обязательны. По умолчанию пустые (не 0).
  • Единица — 3 кнопки: г / мл / шт. По умолчанию «г».
  • Если «шт» — появляется поле «Вес 1 шт, г» (обязательное).
  • Если «мл» — появляется поле «Плотность, г/мл» (по умолчанию 1) + галочка «У меня КБЖУ на 100 мл».

Валидация

Кнопка «Сохранить» полупрозрачная, пока форма невалидна. При клике на невалидную:
  • Над кнопками появляется красная подсказка «Заполните: Название, Группа, ...».
  • Невалидные поля подсвечиваются красной рамкой.
  • Курсор прыгает в первое невалидное.

Обязательные: Название, Группа, все 4 поля КБЖУ. При единице «шт» — ещё вес 1 шт.

Автоматическая плотность ⏳ планируется

Идея. При вводе названия система подставляет плотность из справочника: молоко → 1.03, мёд → 1.42, масло растительное → 0.92, вода → 1.0 и т.д.
Сейчас не работает. Поле плотности заполняется вручную. Дефолт — 1.

Проверка на дубликаты

Зачем. Пользователь создаёт «Молоко Простоквашино 3.2%», а в базовой базе уже есть «Молоко 3.2%». Без проверки получится дубликат.

Как работает. Только при создании нового продукта (не при редактировании). Сравнивается с базовой базой и со своими продуктами.

Алгоритм похожести

  • Разбиваем названия на значимые слова — длиной 3+ букв или цифры.
  • Считаем общие значимые слова.
  • +1, если марки совпадают и не пустые.
  • Порог — оценка 2 и выше. Продукты с меньшей оценкой не показываются.

Пример. Создаём «Молоко Простоквашино 3.2%»:

Продукт в базеОбщие словаОценкаПоказывать?
Молоко 3.2%молоко, 3, 23Да
Молоко 2.5%молоко, 22Да
Молоко обезжиренноемолоко1Нет
Кефир 1%—0Нет

Сортировка результата: по убыванию оценки, при равной — по алфавиту. Показываются все совпадения.

  • 📚 — из готовой базы. ⭐ — свой продукт.
  • «Отмена» — закрывает модалку дубликатов. Форма продукта остаётся открытой, поля на месте. Пользователь может поменять название или вообще закрыть форму.

Редактирование существующего продукта

  • Правый клик / долгий тап по своему продукту в пикере → «✎ Редактировать».
  • Форма открывается поверх пикера, с заголовком «Редактировать продукт».
  • Все поля предзаполнены из продукта.
  • Если у продукта была галочка «КБЖУ на 100 мл» — в полях КБЖУ показываются исходные числа (kbzhuMl), галочка стоит, плотность заполнена.
  • При сохранении — обновляется существующая запись, не создаётся новая. Проверка на дубликаты не срабатывает.

storage.js — функции продуктов

Все операции с продуктами — через storage.js. Напрямую с IndexedDB не работаем.

Готовая база (в коде)

  • getBaseProductGroups() — 19 групп.
  • getBaseProducts() — все 309 продуктов. При чтении каждому добавляется source: 'base'.
  • getBaseProduct(id) — один по ID.
  • searchBaseProducts(query) — поиск только по готовой.

Своя база (IndexedDB)

  • getAllProducts() — все свои.
  • getProduct(id) — сначала ищет в своей, потом в готовой.
  • saveProduct(product) — сохранить свой. Присваивает product-NNN, ставит createdAt, source: 'own'.
  • deleteProduct(id) — удалить свой.

Объединённые

  • searchProducts(query) — поиск по обеим базам. Свои ⭐ первыми.
  • getProductsByGroup(group) — по группе, свои + готовые.

Заглушки (ещё не сделано)

  • getProductsByBrand(brand) — по марке. ⏳ планируется
  • getOverriddenProducts() — только переопределения. ⏳ планируется
  • getUsedProducts() — какие продукты используются в рецептах. ⏳ планируется
