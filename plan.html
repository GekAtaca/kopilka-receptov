Архитектурный рефакторинг (осознанно отложено):
  • Управление состоянием. Сейчас: ванильный JS, ручная синхронизация DOM и базы, полная перерисовка через innerHTML. Проблема: дублирование логики, баги рассинхронизации. Решение (позже): ввести простой Store (объект состояния + подписки), убрать полную перерисовку, вынести общую логику карточек в одно место. Переход на Vue/React — только если проект вырастет до 50+ экранов (требует сборки, усложняет workflow).
  • CSS-специфичность. Сейчас: !important, конфликты каскада. Решение (постепенно): не добавлять новые !important без нужды, использовать :where() для снижения специфичности, не создавать селекторы без привязки к контексту (как было с .modal-recipe-box в antichny.css).
Обязательное правило: новые фичи пишем сразу «правильно» — без ручной синхронизации, с точечными обновлениями (не innerHTML всей сетки), с выносом общей логики. Старый код не переписываем, но новый — только чистый. Это способ не увеличивать клубок, а не распутывать старый.
