IndexedDB — где что живёт

Всё живёт в IndexedDB. Не в localStorage. Причина: рецептов будет 150+, будут фото, будут версии. localStorage (5–10 МБ) не хватит.

storage.js — все операции

Файл app/js/storage.js. Снаружи объект Storage. Внутри — вся работа с IndexedDB. Следующий ИИ просто вызывает Storage.saveRecipe(), не думая про IndexedDB.

Фолбэк. Если IndexedDB недоступна (Safari приватное окно) — saveSetting/getSetting молча работают через localStorage. Сайт не падает.

Ядро

  • init() — открыть базу, создать 9 таблиц, запустить миграцию.
  • seedDemoRecipes() — залить 9 демо-рецептов при первом запуске. Флаг demoSeeded = true.
  • getStats() — сколько рецептов и продуктов.

Настройки (универсальные)

  • getSetting(key) / saveSetting(key, value) / deleteSetting(key).

Рецепты работает

  • saveRecipe(recipe) — сохранить. Без id — выдаст recipe-NNN. Автоподстановка createdAt/updatedAt.
  • getRecipe(id) — получить один.
  • getAllRecipes() — все.
  • deleteRecipe(id) — удалить.

Заглушки по рецептам

  • duplicateRecipe, getRecipesByTag, getRecipesByMeal, getRecipesBySource, searchRecipes, getRecipesCanCook, deleteRecipesBySource.

Продукты работает

  • Готовая база: getBaseProductGroups, getBaseProducts, getBaseProduct, searchBaseProducts. При чтении каждому добавляется source: 'base'.
  • Своя база: getAllProducts, getProduct (сначала своя, потом готовая), saveProduct, deleteProduct.
  • Объединённые: searchProducts, getProductsByGroup.

Заглушки по продуктам

  • getProductsByBrand, getOverriddenProducts, getUsedProducts.

Отметки работает

  • addMark(type, recipeId, extra) — добавить. extra необязательный.
  • removeMark(type, recipeId, extra) — убрать. Без extra — все записи этого типа и рецепта.
  • getMarks(type) — все отметки одного типа.
  • isMarked(type, recipeId) — есть ли отметка у рецепта.
  • getAllMarks() — всё сразу объектом { favorite, cooked, want, plan }.
  • clearMarks(type) — убрать все отметки одного типа. Без типа — очистить всё.

Теги работает

  • saveTag(tag) — сохранить свой. Без id — выдаст tag-NNN.
  • getAllTags() — только свои.
  • deleteTag(id) — удалить свой.
  • getAllTagsMerged() — свои + базовые (btag-NNN). Сначала свои, потом базовые.

Кладовая, План, Корзина заглушки

  • savePantryItem / getPantry / deletePantryItem
  • savePlanItem / getPlan / deletePlanItem / getPlanByTab / clearPlan
  • saveShoppingItem / getShopping / deleteShoppingItem / clearShopping

Таймеры заглушки

  • saveTimer, getTimers, updateTimer, deleteTimer, getActiveTimers, getTimersForRecipe.
Как хранится таймер. Не «осталось 5 минут», а «должен сработать в 15:42:30». При открытии сайта система считает разницу. Если сайт был закрыт — время всё равно идёт.

Фото заглушки

  • savePhoto(blob), getPhoto(id), deletePhoto(id).
Сжатие фото. Перед сохранением — 1200px по длинной стороне, качество 80%. Размер 200–300 КБ вместо 3–5 МБ.

Экспорт / импорт заглушки

  • exportAll, importAll, exportRecipes, exportProducts, importRecipes, importProducts, getLastBackupDate, setLastBackupDate.

Опасное

  • clearAll() — сбросить всё. С подтверждением. Пока заглушка.

Защита данных

Автосохранение. Каждое изменение сразу сохраняется в IndexedDB. Кнопку «Сохранить всё» жать не надо.
Но это сохранение внутри браузера. Если Safari почистит данные — пропадёт всё. Поэтому нужен бэкап: ZIP-файл со всем содержимым, раз в 3–4 дня напоминание. Реализация — шаг 40 плана.
«Добавить на экран Домой». Если сайт добавлен на экран «Домой» — Safari не чистит данные. Единственная 100% защита.

Даты и ID

ID рецепта — числа: recipe-001, recipe-150. Не транслит из названия — иначе два «Салата» затрут друг друга. У продуктов: свои — product-NNN, готовые — транслит (milk-3-2).
Все даты — числа (timestamp в миллисекундах). 1728562950000. Удобно сравнивать, сортировать, показывать в любом виде.

Миграции схемы

Сейчас не пишем. Если завтра понадобится добавить поле в рецепт — пересоздаём базу (данных мало). Напишем, когда данных станет жалко (150 рецептов, база продуктов, кладовая).

Правила работы с хранилищем

Не работать с IndexedDB напрямую. Только через storage.js.
Не хранить в localStorage. Всё уже переехало в IndexedDB. localStorage очищен.
Дублирование const в одном файле ломает всё. Одна SyntaxError валит весь файл. Перед вставкой большого блока с константой — проверить поиском, не объявлена ли уже.
Если функция пишет в общий объект — в начале должна создавать его, если нет. Не полагаться на то, что кто-то вызвал инициализацию раньше.
setTimeout, который прячет заставку, — в самом начале boot(). До всех await. Иначе при ошибке заставка висит вечно.
