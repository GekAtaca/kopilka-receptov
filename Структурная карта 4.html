2 · Кто пользователь

Личный проект для себя. Не для клиента, не для портфолио.

Главное

  • Не программист. Работает в VS Code и GitHub Desktop, код копирует.
  • Windows 11. iPhone 13, iPad Air 11 (M2), ПК.
  • Внимательна к деталям. Заметит нечитаемый текст, кривую линию, лишние полосы.
  • Устаёт от длинных инструкций. Один шаг за раз: сделала → сохранила → обновила → показала → следующий.
  • Лучше понимает визуально. Скриншоты работают. Длинные тексты — хуже.
  • Есть вкус. Отклоняет то, что не подходит, объясняет почему.
  • Честная. Скажет прямо: «не нравится», «убери», «ты торопишься».
В прошлой сессии (5 октября) ИИ несколько раз нарушал правило «сначала решение, потом код» — стрелял кодом, отвечал на незаданные вопросы. Пользователь это заметил и попросил остановиться. Важно: не спешить. Сначала согласовать — потом код.

3 · Как работать с ИИ

  1. Перед отправкой кода — свериться с этой картой. Не по памяти.
  2. Один шаг за раз. Сделала → сохранила → обновила → показала → следующий.
  3. Код — целым файлом или целым блоком, не «замени строчку».
  4. Сложное дроби на шаги. План → черновик → проверка → правки.
  5. Давай альтернативы, где они есть (2–3 варианта).
  6. Пользователь поправил — исправляйся сразу.
  7. Если сомневаешься — спроси, не додумывай.
  8. Сначала решение — потом код. Это важное правило, добавлено после 5 октября.
  9. Не спешить. Лучше уточнить и сделать один раз, чем дважды.

5 · Оформление: стили, палитры, фоны, темы

Идея. Оформление собирается из 4 независимых слоёв. Пользователь выбирает любую комбинацию:
  1. Стиль — 8 штук
  2. Палитра + оттенок — 9 палитр × 5 оттенков = 45 цветовых комбинаций
  3. Фон — 20 базовых + свои
  4. Тема — светлая / тёмная (инверсия)

Как работает. Стиль задаётся атрибутом data-style="xxx" на <body>. Все 8 CSS-файлов подключены в <head> через <link>. Активируется только тот, что совпадает с data-style. Переключение — мгновенное, без перезагрузки.
«Нежный» — эталон. В nezhny.css только комментарий — он ничего не переопределяет. Все переменные по умолчанию стоят в card.css.

5.3. Фоны 🔄 работает, но не финализировано

В папке images/ — 20 картинок (файлы 01–20, номер 06 отсутствует).

Как работает фон в коде.
  1. На странице два слоя: bg-blur (размытая) и bg-sharp (чёткая) — оба внутри .bg-layer.
  2. Слой .bg-layer — position:fixed; z-index:0; inset:0.
  3. Фон — НЕ через background-image (в этом проекте Safari не отрисовывает) — только через <img>.
  4. При выборе картинки в панели — оба изображения получают одинаковый src.
Открытый вопрос: как показывать фон. Мы обсуждали три подхода, ни один не принят окончательно:
  • A. Простой. Картинка обрезается по object-fit:cover — заполняет весь экран. Полос не бывает, но вертикальные картинки на горизонтальных экранах сильно обрезаются.
  • Б. Размытая подложка. Внизу — размытая картинка на весь экран, сверху — чёткая. Пробовали, не понравилось («полоски»).
  • В. Плавное растворение. Чёткая картинка целиком (object-fit:contain) + маска по краям + размытая подложка. Обсуждали, код не написан.
Открытый вопрос: редактор позиции фона. Идея была: рамка, которую пользователь таскает, чтобы выбрать нужную часть картинки. Попробовали — не заработало (превью уже обрезано, координаты не совпадают). Не решено.
Компромисс на будущее: три отдельных набора позиций (ПК / iPad / iPhone), потому что пропорции экранов разные. Настройка на одном устройстве не должна влиять на другое.

⚡ Важно: оформление — локальное

Синхронизируются только данные — рецепты, план, покупки, кладовая.

Оформление — локальное у каждого:

  • Стиль (Нежный / Журнал / ...) — у каждого свой.
  • Палитра + оттенок — у каждого своя.
  • Фон — у каждого свой (или без фона).
  • Позиция фона (если решим) — у каждого своя.
  • Тема (светлая / тёмная) — у каждого своя.

Пример: у тебя — фон с русалкой, у парня — без фона. Или у тебя фон с водой, у парня фон с лесом. Данные — общие, вид — свой.

18 · Известные баги браузеров

18.1. iOS Safari: position:fixed с z-index:-1

Симптом. Фоновый слой с position:fixed; z-index:-1 на iPhone/iPad ведёт себя непредсказуемо:
  • При скролле фон уезжает вверх — снизу видно пустоту (розовый body).
  • Или наоборот — фон перекрывает контент (шапка, тулбар, содержание исчезают).
  • На ПК и iPad чаще всего работает, на iPhone — почти всегда ломается.
Причина. iOS Safari при скролле сворачивает адресную строку и пересчитывает все position:fixed элементы. Минусовый z-index при этом «теряется».
Решение (работает).
  1. Фон — position:fixed; z-index:0 (не минусовый!).
  2. Весь контент — в обёртке <div class="app"> с position:relative; z-index:1.
  3. На .bg-layer — -webkit-transform: translateZ(0); transform: translateZ(0); will-change: transform; (создаёт GPU-слой, чтобы Safari не «терял» элемент).

18.2. iOS Safari: полоса внизу экрана

Симптом. Даже при правильной работе фона, снизу остаётся **светлая полоса** между картинкой и нижней панелью Safari. Она видна особенно на тёмных фонах.
Что пробовали — не помогло:
  • bottom:-100px на .bg-layer.
  • height:100lvh (Large Viewport Height).
  • Тёмный псевдоэлемент ::after под панелью.
Решение — оставили как есть. Полоса мелкая, сливается со светлой палитрой. Не критично.

18.3. iOS/iPadOS Safari: агрессивный кэш CSS/JS

Симптом. Изменения в CSS не видны на iPhone/iPad, хотя на ПК всё обновилось.
Решение: открыть сайт в приватном окне Safari. Или очистить кэш в настройках. Или подождать.

18.4. iOS Safari: background-image не отрисовывается

Симптом. В этом проекте Chrome/Safari на iPhone не отображают фон через background-image: url(...) на <body> или <html>. Картинка загружается (видно в Network), но не рисуется.
Решение: использовать <img> с position:fixed и object-fit:cover. Работает всегда.
