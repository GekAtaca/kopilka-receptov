Структура одного рецепта

Это фундамент проекта. От структуры рецепта зависит всё: как считается КБЖУ, как работают версии, где хранятся отметки.

Приём пищиДаЗавтрак / Обед / Ужин / Перекус

2. Фото

  • Галерея — любое количество фото. Необязательно.
  • Главное фото — первое в галерее, оно же в маленькой карточке.
  • Порядок — перетаскиванием.

3. Теги и заметка

  • Теги — до 5 главных + полный список. См. раздел «Теги».
  • Заметка — свободный текст. Например: «Брать молоко 3.2%, не 2.5%».

4. КБЖУ, порции и вес

ПолеОбязательно?Пример
ИнгредиентыДа, минимум 1—
Эталонное количество порцийДа (по умолч. 2)2
КБЖУСчитается из ингредиентов195 ккал · Б 20 · Ж 7 · У 16
Вес порцииСчитается или вводится вручную120 г
Вес готового блюдаАвто из ингредиентов240 г
КБЖУ считается автоматически из ингредиентов.
У каждого продукта в базе есть КБЖУ на 100 г. Система пересчитывает на нужный вес, складывает все ингредиенты, делит на количество порций.
Пример. Овсянка 60 г (210 ккал) + Молоко 200 г (120 ккал) + Мёд 20 г (60 ккал) = 390 ккал. Порций 2 → 195 ккал на порцию.
Вручную КБЖУ не вводится. Только через ингредиенты.

Эталонное количество порций

Что это. То, на что рассчитаны ингредиенты. Вводится в редакторе. Например: ингредиенты на 2 порции. Это «база». У демо-рецептов эталон разный: овсянка 1, паста 2, суп 3.
Стартовое при открытии большой карточки = 4. Независимо от эталона. Пользователь обычно готовит на 4 порции.
Как считается коэффициент: 4 / эталон. Овсянка: 4/1 = ×4 → 60 г × 4 = 240 г. Паста: 4/2 = ×2. Суп: 4/3 = ×1.33 → 600 г × 1.33 = 800 г.
Сохранение: выбранное количество сохраняется в IndexedDB (тип portions). Открыла снова — покажет последнее сохранённое.
Сброс на 4: клик по числу порций.
КБЖУ на порцию НЕ пересчитывается. Одна порция всегда той же калорийности, сколько бы порций ты ни готовила.

Вес готового блюда

По умолчанию — сумма веса всех ингредиентов. Можно переопределить вручную (если взвесила готовое). Тогда вес порции = вес блюда / порции.
Если не взвешивала — вес порции примерный, с пометкой «≈».

5. Ингредиент (внутри рецепта)

ПолеОбязательно?Пример
Ссылка на продукт из базыДаmilk-3-2
НазваниеАвто из базыМолоко 3.2%
КоличествоДа200
ЕдиницаДамл / г / шт
  • Ссылка на продукт — через неё КБЖУ пересчитывается автоматически, если поправишь продукт в базе.
  • В рецепте — короткое имя ингредиента (shortName из базы). Полное имя с маркой хранится в базе продукта. Подробнее — в products.html.
  • Комментариев у ингредиента нет. Всё «как делать» — в шагах.
  • Порядок — перетаскиванием.
  • Если продукт удалён из базы — у ингредиента маленький значок ⚠. Без общей надписи «КБЖУ неполное».

6. Время

ПолеОбязательно?Пример
ЭтапыНетПодготовка 10 мин, Маринад 15 мин, Готовка 15 мин
Общее времяСчитается40 мин

Готовые этапы: Подготовка, Маринад, Готовка, Ожидание, Остывание, Замес, Расстойка, Запекание, Варка, Жарка, Тушение + свои.

Общее время = сумма всех этапов. В карточке одно. Клик → раскрывается список этапов. Если этапов нет — вводится одно число вручную.

7. Шаги

ПолеОбязательно?Пример
НомерАвто1, 2, 3
ТекстДаРазогреть сковороду
Порядок—Перетаскиванием
  • Отдельные поля. Жмёшь «+ Добавить шаг» → новое поле. Не одним текстом с переносами строк.
  • Номера ставятся автоматически. Удалила шаг — номера пересчитались. Переставила — тоже.
  • Только текст. Без форматирования, без фото, без таймера.

8. Устройство готовки

  • Одно устройство (или ни одного).
  • Список: Сковорода / Духовка / Мультиварка / Аэрогриль / Без готовки / ...
  • Позже — свои устройства в настройках.

9. Отметки

Хранятся отдельными списками, не внутри рецепта. В таблице marks. Ключ: type:recipeId[:extra].
  • ❤ Избранное — понравилось.
  • 👨‍🍳 Приготовлено — отмечено как приготовленное (с датой).
  • 🔖 Хочу приготовить — хочу когда-нибудь приготовить.
  • 📅 В план — в одну из вкладок: Семейный / Для ребёнка / События (заглушка). extra = family / child / events.
  • ✅ Галочка ингредиента — отметка «взял ингредиент», тип ingredient. Привязана к названию ингредиента.
  • 🔢 Порции — выбранное количество, тип portions.

10. Служебное

  • Версии — минимум 1. Список.
  • Текущая версия — какая показывается.
  • Дата создания — авто.
  • Дата изменения — авто.

Правила рецепта

  1. Обязательные: название, хотя бы 1 ингредиент.
  2. КБЖУ всегда считается из ингредиентов. Вручную не вводится.
  3. Округление: калории — до целого, Б/Ж/У — до одного знака.
  4. Вес готового блюда — авто из ингредиентов, можно переопределить вручную.
  5. Уварка не учитывается. Считаем на сырой вес.
  6. Зелень, специи — считаются. Соль — нет. «По вкусу» — без количества.
  7. Масло для жарки — считаем всё.
  8. Этапы времени — готовые + свои. Общее = сумма.
  9. Шаги — только текст. Отдельные поля. Номера авто.
  10. Ингредиенты — без комментариев.
  11. Перестановка — фото, ингредиенты, шаги. Перетаскиванием.
  12. Удаление рецепта — навсегда, с подтверждением. Без архива.
  13. Синхронизация — целевое поведение: чекбоксы, порции, отметки между большой и маленькой карточкой. Пока НЕ реализовано — см. раздел ниже.
  14. Отметки хранятся отдельными списками.
  15. Таймеры — отдельный список. Активный таймер = {ID рецепта, шаг, время окончания}.
  16. Теги — базовые в коде, свои в IndexedDB.
  17. Источник рецепта — выпадающий список: Джулия / Мои / Мама / Интернет.
  18. Ингредиент без КБЖУ — маленький значок ⚠ рядом.
  19. База продуктов — готовая + свои. Марки можно. Экран «База продуктов» — вкладка Кладовой.
  20. Перенос 150 рецептов — вручную, когда база продуктов и большая карточка будут готовы. КБЖУ пересчитывается через базу.

Маленькая карточка рецепта

Текущий статус. Описанное ниже — целевое состояние. Фактически сейчас маленькая карточка рендерится из render.js со старой структурой: 5 иконок на фото, 3 кнопки внизу (🛒 · ✎ Изменить · 🕐 версии при >1). Разделы «Кнопки на фото» и «Нижние кнопки» — пока не реализованы.
План: привести маленькую карточку к карте — отдельным шагом после большой карточки.

Структура (сверху вниз)

  1. Фото (150px). Слева сверху — бейдж приёма пищи. Справа сверху — 4 круглые кнопки 32px: ❤ 👨‍🍳 📅 🔖.
  2. Название — шрифт от стиля.
  3. Теги — до 3. Если больше — 3 главных (самые часто используемые во всей базе). ⏳ планируется
  4. КБЖУ + время — строка.
  5. Ингредиенты с чекбоксами и порциями.
  6. Кнопка «▼ показать все».
  7. Блок устройства готовки (если есть).
  8. Заметка (если есть).
  9. Нижние кнопки: 4 штуки в ряд — [🛒 N] [⏱] [✎ Изменить] [🕐 N из M].

Кнопки на фото

КнопкаЧто делает
❤ ИзбранноеПереключатель. Активно → залита. Синхронизировано с большой карточкой.
👨‍🍳 ПриготовленоПереключатель. Активно → иконка меняется на ✅.
📅 В планОткрывает dropdown с галочками (Семейный / Для ребёнка / События — заглушка).
🔖 Хочу приготовитьПереключатель.

Нижние кнопки

КнопкаЧто делает
🛒 КупитьИконка + число. Отмечено 2 ингредиента → «🛒 +2». Не отмечено → «🛒 N» (все ингредиенты). Работает как в большой карточке.
⏱ ТаймерИконка + число активных таймеров. Клик → модалка таймера.
✎ ИзменитьОткрывает сразу редактор (не большую карточку).
🕐 Версии«N из M». Скрывается, если версия одна.
Кнопки «⋯ Ещё» в маленькой карточке нет. Она есть только в большой. Причина: место дорого, на телефоне 5 кнопок в ряд не влезут.

Ограничение ингредиентов

  • Длинные карточки (есть и устройство, и заметка) → 3 ингредиента.
  • Остальные → 4 ингредиента.
  • Скрытые показывает кнопка «▼ показать все».
Теги в маленькой карточке — обрезка до 3 пока не реализована. Идея: CSS-правило .tags span:nth-child(n+4){display:none}. Сейчас видны все теги, которые есть у рецепта. Отложено до шага «привести маленькую карточку к карте».

Клик по карточке

  • Клик по названию или по фото — открывает большую карточку.
  • Клик по кнопкам внутри (иконки, чекбоксы, порции, нижние кнопки) — большую карточку не открывает. Кнопки работают отдельно.

Что НЕ входит в MVP

  • ⏳ ⏱ Таймер по-настоящему — шаг 38.
  • ⏳ 📅 Сохранение в план — сейчас галочки только визуально.

  • ⏳ Галерея фото — когда будут фото.

Теги в большой карточке

Сейчас — первые 5 из массива recipe.tags. Не по частоте использования, а просто первые.
Целевое: 5 «главных» = самые часто используемые во всей базе рецептов. Когда рецептов станет много (150+), сделаем сортировку по частоте. Пока в базе 9 демо-рецептов, «частота» бессмысленна.

Модалка «Версии» (шаг 38)

Список версий. Пример: Версия 1 · Версия 2. Лёгкий вариант · Версия 3. Без майонеза. Текущая — выделена.
  • Клик по строке → мгновенное переключение на эту версию.
  • Долгий тап / правый клик → «Удалить». Удалили текущую — переключение на предыдущую.
  • Удалили единственную → «Это последняя версия. Точно хотите удалить?» → Да = рецепт удаляется целиком.

Модалка таймера (шаг 38)

Что внутри:
  • Выпадающий список шагов (привязать таймер к шагу). Можно не указывать.
  • Поле времени — минуты / секунды.
  • Тумблер «Со звуком / Без звука».
  • Кнопка «Запустить».
  • Список активных таймеров этого рецепта: «Шаг 3 · 05:32 осталось».
Несколько таймеров — можно. Один рецепт, разные шаги, разные таймеры.
Когда время вышло: окно-уведомление «В рецепте "Овсянка" к шагу 3 закончился таймер». Звук 10 секунд (если включён). Кнопка «Остановить звук».
Таймер продолжает идти, если модалку закрыть. Работает в фоне, пока сайт открыт.
Пуш-уведомления (когда сайт закрыт) — отложены до PWA.
Таймер на удалённом рецепте отменяется автоматически.

Модалка редактирования (шаг 37)

Что можно редактировать: название, фото, теги, КБЖУ и время, ингредиенты, шаги, устройство, заметка, приём пищи.
Что НЕ редактируется: 4 иконки на фото, порции, кнопки нижней полосы.
Кнопки внизу — split button: [Отмена] [Сохранить | ▾].
  • Левая «Сохранить» — сохраняет в текущую версию.
  • Правая «▾» — открывает меню: «Сохранить как новую версию».
«Сохранить как новую версию» — открывает окно «Название версии (необязательно)» + поле. Пишешь «Лёгкий вариант» → «Версия N. Лёгкий вариант». Пусто → «Версия N». Версия 1 не трогается, новая становится текущей.
Крестик = отмена, изменения пропадают. Если модалка осталась открыта (позвонили) — изменения живы.
Если поле обязательное пустое (например, название стёрто) — «Сохранить» не работает, всплывает подсказка.

Модалка «Теги рецепта» (шаг 15 плана)

Открывается кликом по ✎ рядом с тегами.
Часть 1 — теги этого рецепта: список текущих, у каждого крестик. Долгий тап → «Удалить». Под списком — кнопка «+ Добавить тег».
Часть 2 — выбор тега: строка поиска сверху. Список всех тегов по 16 группам. У каждого галочка. Отметила → тег сразу добавился. Если нет в базе — «Создать тег "X"» → «Тега "X" ещё нет. Создать?» → выбираешь группу → «Да».
Удаление тега из рецепта ≠ удаление из базы. Из рецепта — пропадает только здесь. Из базы — в настройках (раздел «🏷 Теги»).

Dropdown «В план» (внутри большой карточки)

Открывается кликом по 📅 на фото. Не шторка снизу, а выпадающий список под кнопкой.
Внутри — три галочки: Семейный / Для ребёнка / События.
Клик — ставит/снимает галочку. Список не закрывается — можно отметить несколько.
Закрыть: клик вне или Escape.
Почему dropdown, а не шторка. Рядом с кнопкой — глаз не прыгает вниз экрана. Видно, к какому рецепту применяешь.

Dropdown «Ещё» (вверх от нижних кнопок)

Открывается кликом по ⋯. Выпадает вверх.
  • 📤 Поделиться — копирует адрес главной страницы в буфер.
  • 📋 Копировать текст — весь текст рецепта в буфер: название, КБЖУ, порции, ингредиенты, шаги, устройство, заметки.
  • 🖨 Печать — системное окно печати браузера. Можно «Сохранить как PDF».
  • 🗑 Удалить — удаляет всю карточку со всеми версиями. Подтверждение «Удалить рецепт со всеми версиями?».

Фото на весь экран

Клик по фото в большой карточке → разворачивается на весь экран. Крестик в правом верхнем углу — закрыть.

Синхронизация — целевое

ЦЕЛЕВОЕ, но пока НЕ реализовано.
  • Отметки ❤ 👨‍🍳 🔖 — синхронизированы (одна запись в marks, обе карточки видят).
  • Чекбоксы ингредиентов и порции — НЕ синхронизированы. Маленькая карточка показывает эталон, большая — стартовое 4 или сохранённое.
  • Когда сделаем синхронизацию — отдельным шагом.

Категории и теги не дублируются.

Перенос рецептов из PDF

Формат. PDF 39,7 МБ. Внутри — картинки с рецептами (не текст). Автоматически перенести нельзя — только OCR, а он ошибётся.
Перенос — только вручную, через редактор рецепта. Когда база продуктов и большая карточка готовы.

Порядок переноса

  1. Сначала — 5 рецептов: Ролл с тунцом, Салат Мимоза, Куриные стожки, Пряная индейка, Печенье протеиновое.
  2. Потом — остальные 145.
  3. Каждый — через ➕ Добавить рецепт. Сразу правильно: с фото (вырезаешь из PDF), с КБЖУ из базы, с порциями.

Что берём из PDF

  • Название (с типом приёма).
  • Фото (вырезаешь и загружаешь через редактор).
  • Ингредиенты с количеством.
  • Шаги (нумерованные).
  • Порции — сначала по умолчанию 2, потом правишь вручную.

Что НЕ берём

  • Срок хранения («//» — 1 день, 2 дня) — не добавляем.
  • Уровень сложности (полоски внизу) — не отдельное поле, через теги.
  • КБЖУ из PDF — не используем. Считаем заново через базу продуктов из ингредиентов.

Открытые вопросы

Смена устройства готовки и корзина. Что происходит с ингредиентами и корзиной, когда в рецепте меняешь устройство готовки. Обсудим, когда будем делать экран «Устройство готовки».
Округление штучных продуктов. Как показывать «1/2 шт.» при смене порций (яйца, бананы, помидоры). Обсудим, когда будем делать пересчёт.
