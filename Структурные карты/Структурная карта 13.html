2 · Как работать с ИИ

Сначала решение — потом код. Пока пользователь не сказала «ок, давай код» — обсуждаем словами.
Один шаг за раз. Сделала → сохранила → обновила → показала → следующий.
Код — целым блоком. «Найди этот текст → замени на этот». Без номеров строк.
Не повторять код, если он уже был дан.
Не забывать про !important, когда старое правило мешает.
При застревании — просить файлы. «Пришли index.html, style.css».
ИИ не может отправлять скрины. Только пользователь.
Если «этого нет» — остановиться и попросить скрин. Не придумывать ещё вариант.
Перед Replace All — предупредить, что замена может задеть лишнее.
Большая задача — разбить на подшаги. Идти по одному.
Потерял нить — сказать и предложить обновить документацию. Не делать вид, что помню.
Проверка на телефоне — только через Commit + Push. Прямого доступа к файлам на iPad/iPhone нет.
Если задача касается смежного раздела — попросить нужный файл. Не додумывать.
Если пользователь устала — остановиться. Короткие неопределённые ответы — не значит «всё работает». Спросить конкретнее.
Если «не то» без объяснений — предложить 2–3 варианта.
Не переспрашивать то, что уже решено. НО: если пользователь сама вернулась к вопросу — значит, передумала. Обсуждаем заново.
Подробнее — start.html.

storage.js — все операции

Снаружи объект Storage. ~51 функция. Внутри — вся работа с IndexedDB. Следующий ИИ просто вызывает Storage.saveRecipe().

Готовы: ядро (init, seedDemoRecipes, getSetting / saveSetting / deleteSetting, getStats), рецепты (4 из 11), отметки (6 из 6), теги (4 из 4), продукты (11 из 11).
Заглушки: кладовая, план, корзина, таймеры, фото, экспорт/импорт.
Фолбэк: если IndexedDB недоступна (Safari приватное окно) — saveSetting/getSetting молча работают через localStorage. Сайт не падает.

Процедура первой загрузки

  1. Заставка: setTimeout 1.2 сек — независимо ни от чего. Ошибка будет видна в консоли.
  2. Storage.init() → открыть базу, создать 9 таблиц. Затем migrateFromLocalStorage().
  3. Storage.seedDemoRecipes() — залить 9 демо-рецептов. Флаг demoSeeded = true.
  4. loadDesignFromStorage() — читает design, designShadowTab, designSectionsCollapsed.
  5. loadSharedFromStorage() — читает bgSettings.
  6. initScreens(savedScreen) — показать экран, применить оформление.
  7. renderAllRecipes() — прочитать рецепты, разложить по секциям.

5 · Рецепт: структура

Это фундамент. От структуры рецепта зависит всё: как считается КБЖУ, как работают версии, где хранятся отметки.

Поля рецепта

Приём пищиДаЗавтрак / Обед / Ужин / Перекус

СложностьНетПростое / Среднее / Сложное

КБЖУ считается автоматически из ингредиентов. У продукта есть КБЖУ на 100 г. Система пересчитывает на нужный вес, складывает, делит на порции. Вручную КБЖУ не вводится.
Эталонное количество порций. То, на что рассчитаны ингредиенты. Стартовое при открытии большой карточки = 4 (пользователь обычно готовит на 4). Коэффициент = 4 / эталон. Сохраняется в IndexedDB (тип portions). Сброс на 4 — клик по числу. КБЖУ на порцию НЕ пересчитывается.

Версии — как папка

Снаружи один рецепт, внутри — список версий. На Главной одна карточка. Общие у папки: название. Своё у каждой версии: название версии, фото, теги, источник, сложность, время, устройство, заметка, ингредиенты, шаги, КБЖУ, все отметки, галочки ингредиентов, порции.

Правила рецепта

  1. Обязательные: название, хотя бы 1 ингредиент.
  2. КБЖУ всегда считается из ингредиентов.
  3. Округление: калории — до целого, Б/Ж/У — до одного знака.
  4. Вес готового блюда — авто из ингредиентов, можно переопределить.
  5. Уварка не учитывается. Считаем на сырой вес.
  6. Зелень, специи — считаются. Соль — нет. «По вкусу» — без количества.
  7. Масло для жарки — считаем всё.
  8. Шаги — только текст. Отдельные поля. Номера авто.
  9. Ингредиенты — без комментариев.
  10. Удаление рецепта — навсегда, с подтверждением. Без архива.
  11. Версии — как папка. Один рецепт снаружи, список версий внутри.
  12. Отметки хранятся отдельными списками (таблица marks).
  13. Таймеры — отдельный список. Активный = {ID рецепта, шаг, время окончания}.
  14. Ингредиент без КБЖУ — маленький значок ⚠.
Подробнее — recipes.html.

Модалка редактирования (шаг 37)

Одна модалка для создания и редактирования. При создании — 3 вкладки (✍ Вручную · 📋 Текст · 🔗 Ссылка), «Текст» и «Ссылка» — заглушки. При редактировании — вкладок нет.
Кнопки внизу — split button: [Отмена] [Сохранить | ▾]. Левая «Сохранить» — в текущую версию. Правая «▾» — «Создать новую версию».
«Создать новую версию»: правки попадают в новую версию. Старая не трогается. Активной становится новая. Окно «Название версии (необязательно)».
Черновики — НЕ в этом шаге. Закрыла без сохранения — правки пропали.
Фото — НЕ в этом шаге. Ждём слой 4.
Теги — в этом шаге. Модалка выбора тегов переезжает из шага 15 внутрь шага 37.
Отметки ингредиентов при редактировании — точечная чистка. Для исчезнувших ингредиентов удаляем галочки. Остальные не трогаем.

Модалка «Версии» (шаг 38)

Список версий. Текущая — выделена. Клик по строке — мгновенное переключение. Долгий тап / правый клик — «Удалить». Удалили единственную — «Это последняя версия. Точно хотите удалить?» → Да = рецепт удаляется целиком.

Модалка таймера (шаг 38)

Выпадающий список шагов, поле времени, тумблер «Со звуком / Без звука», кнопка «Запустить», список активных таймеров. Несколько таймеров — можно. Когда время вышло — окно-уведомление + звук 10 сек + «Остановить звук». Таймер продолжает идти, если модалку закрыть. Пуш — после PWA. Таймер на удалённом рецепте отменяется.

Модалка «Теги рецепта» (шаг 15 плана)

Открывается кликом по ✎. Часть 1 — теги этого рецепта (крестик, долгий тап → удалить, «+ Добавить тег»). Часть 2 — выбор тега (поиск, список по 16 группам, галочки, «Создать тег "X"»). Удаление из рецепта ≠ удаление из базы.

Dropdown «В план»

Открывается кликом по 📅. Не шторка, а выпадающий список под кнопкой. Три галочки: Семейный / Для ребёнка / События. Клик — ставит/снимает, список не закрывается. Закрыть: клик вне или Escape.

Dropdown «Ещё»

Открывается кликом по ⋯. Выпадает вверх. 4 пункта: 📤 Поделиться · 📋 Копировать текст · 🖨 Печать · 🗑 Удалить.

Синхронизация — целевое, не реализовано

Отметки ❤ 👨‍🍳 🔖 — синхронизированы. Чекбоксы ингредиентов и порции — НЕ синхронизированы. Когда сделаем — отдельным шагом.

8 · База продуктов

Зачем. КБЖУ рецепта считается из ингредиентов. Ингредиенты берутся из базы продуктов.

Две части

1. Готовая база — файл products-base.js в коде. 309 продуктов в 19 группах. КБЖУ из официальных российских справочников. Править напрямую нельзя — но можно скопировать в свою базу и там править.
2. Своя база — что пользователь добавила сама. IndexedDB, таблица products. Создавать, править, удалять.
При поиске обе базы объединяются. Сначала свои (⭐), потом готовые. Внутри — группировка по типу.
