2 · Кто пользователь

Личный проект для себя. Не для клиента, не для портфолио.

Главное

  • Не программист. Работает в VS Code и GitHub Desktop, код копирует.
  • Windows 11. Техника: iPhone 13, iPhone 16 Pro Max, iPad Air 11 (M2), ПК.
  • Внимательна к деталям. Заметит нечитаемый текст, кривую линию, лишние полосы.
  • Устаёт от длинных инструкций. Один шаг за раз.
  • Лучше понимает визуально. Скрины со стрелочками работают лучше всего. Схемы с отступами (деревом) — НЕ понимает.
  • Есть вкус. Отклоняет то, что не подходит.
  • Честная. Скажет прямо: «не нравится», «убери», «ты торопишься», «ты меня запутал».
  • Разбирается в DevTools. Console, Network, Elements. Умеет Disable cache.
  • Не разбирается в коде. Инструкции — максимально пошаговые, без номеров строк.
  • Хочет вместе решать дизайн. Обсуждать, задавать вопросы, спорить.

3 · Как работать с ИИ

Главные правила (не нарушать)

Перед отправкой кода — свериться с этой картой. Не по памяти.
Сначала решение — потом код. Пока пользователь не сказал «ок, давай код» — обсуждаем словами.
Обсуждаем одну фичу (или один подшаг) — до конца. Потом сразу код.
Один шаг за раз. Сделала → сохранила → обновила → показала → следующий.
Код — целым блоком. «Найди этот текст → замени на этот». Или «поставь курсор в конце строки X → Enter → вставь».
Никаких номеров строк. Только поиск по тексту.
Не повторять код, если он уже был дан.
Сомневаешься — спроси. Не гадай.
Если пользователь говорит «этого нет» — немедленно остановиться и попросить скрин. Не придумывать ещё один вариант правки.
При застревании — просить файлы. «Пришли index.html, style.css».
Не забывать про !important, когда старое правило мешает.
ИИ не может отправлять скрины. Только пользователь.
Схемы с отступами (деревом) пользователь НЕ понимает. Словами, таблицами, плоским списком.
Сначала обсуждать дизайн полностью — потом писать код.
Если чувствуешь, что теряешь нить — ОБЯЗАТЕЛЬНО сказать пользователю и предложить обновить структурную карту. Не делать вид, что помнишь.
Перед заменой через «Replace All» — предупреждать, что может задеть лишнее. Урок 9 октября 2026: замена getDesignFor(activeDesignScreen) затронула саму функцию getActiveDesign и вызвала рекурсию.

Commit + Push — обязательно перед проверкой на устройстве

У пользователя нет прямого доступа к файлам на iPhone/iPad. Проверить — только через GitHub Pages.
Если пользователь смотрит на iPhone/iPad — сначала: «сохрани, обнови на ПК; Commit + Push; подожди 1–2 минуты; открой на устройстве».

3.2. Что работает / что не работает в объяснениях

Работает:
  • «Найди этот текст → замени на этот».
  • «Поставь курсор в конце строки X → Enter → вставь это».
  • «Удали эти строки целиком».
  • Скрины от пользователя — со стрелочками.
Не работает:
  • Схемы «деревом» с отступами.
  • Номера строк в инструкциях.
  • ИИ не может отправлять скрины.
  • Ссылаться на «мы же помним».

3.3. Как войти в курс дела (для нового ИИ)

Порядок: прочитать карту → сказать своими словами, что понял → спросить, что уточнить → и только потом работать.

3.4. Отдельные правила поведения

Если пользователь устала — остановиться. Короткие неопределённые ответы — это не значит «всё работает». Спросить конкретнее.
Если «не то» без объяснений — предложить 2–3 варианта. Не мучить вопросом «что именно не то?».
Не переспрашивать то, что уже решено. НО: если пользователь сама вернулась к вопросу — значит, передумала. Обсуждаем заново.

6.3. Хранилище ✅

Ключ design в localStorage: 
design = {
  home:      { style, palette, shade, shadow, fabShadow, theme, bg },
  favorites: { ... },
  plan:      { ... },
  pantry:    { ... }
}
Черновик designDraft — в памяти, не в localStorage. Живёт, пока открыта панель. Обнуляется при закрытии.
Что работает в коде:
  • loadDesignData() — загружает структуру.
  • getDesignFor(screen) — сохранёнка.
  • getActiveDesign() — черновик или сохранёнка. Возвращает черновик, если он есть. Иначе — сохранёнку.
  • setDesignFor(screen, patch) — сохранить (используется в 4.3).
  • applyDesignFor(screen) — применить к body.
  • syncMockupScope() — применить черновик к макету.

6.4. Подшаг 4.1a — инфраструктура ✅ сделано

Что сделано:
  • HTML: на макете класс dm-scope. Стало: <div class="design-panel-mockup dm-scope">.
  • JS: функция syncMockupScope(). Ставит data-style, data-palette, data-shadow, data-theme на макет. Вызывается при открытии панели.
  • CSS в style.css: дефолтные переменные «Нежного» и правила тёмной темы макета перевешены на .dm-scope.
  • CSS в card.css: правила --plate-bg / --plate-text (для насыщенных оттенков и тёмной темы) распространены на .dm-scope.
Все классы внутри макета — с префиксом dm-. Никаких .chip, .card, .contents внутри макета — только свои.
Список (сверху вниз, как в HTML):
  • .design-panel-mockup — обёртка макета (внешняя). У неё же класс dm-scope. На ней лежат data-style, data-palette, data-shadow, data-theme.
  • .dm-header — полоска «шапки».
  • .dm-logo — кружок слева в шапке.
  • .dm-icons и .dm-icons span — три точки справа в шапке.
  • .dm-contents — полоска «содержания».
  • .dm-chip — чипы внутри содержания (3 штуки).

6.6. Подшаг 4.2 — черновик ✅ сделано

Как работает:
  1. Открытие панели: designDraft = { ...сохранёнка текущего экрана }.
  2. Клик по стилю / палитре / оттенку / тени / теме / фону — меняет поле в designDraft. Не трогает страницу. Обновляет макет и подсветку чипов.
  3. Клик по фону — в черновик пишется имя фона, квадратик подсвечивается. Макет пока не реагирует (см. следующий подшаг). Страница не меняется.
  4. Тумблер 🌞/🌙 — в черновик. Макет темнеет/светлеет.
  5. Крестик / клик по тёмному фону / Escape — designDraft = null. Панель закрывается.
  6. Кнопка «Применить» — пока ничего не делает (подшаг 4.3).
Что подтверждено явно: черновик работает (клик в панели не трогает страницу), макет перекрашивается, плашки в макете меняются, тени в макете видны.
Что НЕ подтверждено в явных словах: закрытие через крестик / клик по тёмному фону / Escape (выбрасывают ли они черновик). При следующей проверке панели — уделить этому минуту.
Черновик теряется при перезагрузке страницы — это нормально.
designDraft живёт только в памяти, пока открыта панель. Если перезагрузить страницу или закрыть вкладку — черновик пропадает. Настройки вернутся к сохранёнке (то, что лежит в design[экран]).
Это не баг. Черновик — временная штука, сохраняется только через «Применить».
Побочные правки, сделанные в 4.2:
  • Подложка макета — цвета mix(c1, c2), как у настоящего фона. Чтобы тень карточки в макете было видно.
  • Тени карточки в макете усилены (плотнее, компактнее).
  • Переменные --plate-bg / --plate-text переопределены на .dm-scope (иначе чипы, теги, кнопки не перекрашивались бы при смене палитры в черновике).
Урок: переменные на body не наследуются в .dm-scope автоматически.
Если CSS-переменная объявлена как body{--что-то:...}, то на .dm-scope она приходит уже посчитанной, «застывшей». Если внутри макета переменная должна пересчитываться по-новому — её надо переопределить на .dm-scope отдельно.
Пример: --plate-bg / --plate-text в card.css висели на body, и макет их брал оттуда же — старыми. Пришлось продублировать на .dm-scope.
Что делать, если в будущем появится новая переменная на body: подумать, должна ли она работать в макете. Если да — добавить такое же правило для .dm-scope. Если только для настоящей страницы — ничего не делать.

6.7. Обсуждено, не сделано — фон в макете ⏳

Решение: вариант А (упрощённый показ).
  • Раньше решали: «фон в макет не тащим». Пересмотрели: тащим.
  • Внутри .dm-scope появляется <img> с картинкой фона, object-fit:cover.
  • Без blur-слоя — на маленьком размере не читается.
  • Без мягких краёв (маски) — на макете не нужна.
  • Без позиции и зума — это тонкая настройка, место на большой странице.
  • Фон виден сразу при открытии панели (берётся из черновика, а если черновика нет — из сохранёнки).
  • Клик по другому фону — меняет designDraft.bg, макет обновляется.
Позиция фона (когда таскаешь в редакторе) в макете НЕ видна — и это нормально. Макет показывает только сам фон, без смещения и зума. Если пользователь подвигает фон в редакторе и не увидит разницы в макете — так и задумано. Позиция отработает на реальной странице при «Применить».
Почему так: позиция на 320px макета — это микроскопические сдвиги, которые не читаются. Показывать их — только сбивать с толку.

6.8. Подшаг 4.3 — кнопка «Применить» ⏳ следующее

6.13. Позиция фона — вариант В (гибрид) ⏳ подшаг 7

Тонкость, требует решения в подшаге 7. Кнопка «📐 Позиция» в панели сейчас закрывает панель (а закрытие панели = выброс черновика). Значит: пользователь накликал в черновике новый стиль и тени, потом нажал «Позиция» — черновик потеряется без предупреждения.
Варианты решения:
(а) Позиция редактируется отдельно от черновика. Черновик не имеет к ней отношения. Тогда — оставить как есть.
(б) Открытие «Позиции» сохраняет черновик во временном буфере, редактор поверх панели, при закрытии — вернуть. Сложнее.
(в) Кнопка «Позиция» в панели не закрывает панель, а открывает редактор поверх. При закрытии редактора — панель с черновиком на месте.
Обсудить при разработке подшага 7.
Как работает. Позиция и зум — по умолчанию общие для картинки. Можно «отвязать» для конкретного экрана.
Переключатель в редакторе позиции: (●) Общая / ( ) Своя для этого экрана.

6.16.1. Кнопка «Посмотреть» — болванка ⏳

Кнопка есть, но ничего не делает. Логика будет в подшаге 6.
  • iPhone (ширина < 800px) — кнопка видна. Нажатие пока ничего не делает.
  • iPad (ширина ≥ 800px) — кнопки нет вообще. Там две колонки и макет, отдельная кнопка не нужна. Это не баг.
  • ПК (ширина ≥ 800px) — то же, что на iPad.
Почему так. Кнопка «Посмотреть» — только для телефона. На телефоне макет не помещается, поэтому пользователь нажимает «Посмотреть» → панель уезжает → он видит экран → снизу плашка [Применить] [Вернуться].
Известное ограничение 4.2 на iPhone (ширина < 800px): клик по стилю / палитре / тени / теме / фону сейчас не показывает ничего.
Почему: макета на телефоне нет, а страница по решению 4.2 не меняется (черновик). Значит, пользователь жмёт Бохо — и визуально ничего не происходит. Ни в макете, ни на странице.
Это не баг, но UX-провал. Решается в подшаге 6: «Посмотреть» покажет результат на весь экран. До этого момента на iPhone панель фактически «слепая» — кликать можно, но увидеть эффект нельзя.
Что делать сейчас: ничего. Просто знать и не паниковать. На iPhone не проверять черновик — проверять на ПК или iPad.

19 · Известные баги браузеров

19.1. iOS Safari: position:fixed + z-index:-1

Решение. Фон — position:fixed; z-index:0, контент в .app с z-index:1.

19.2. iOS Safari: полоса внизу экрана

Оставили как есть.

19.3. iOS/iPadOS Safari: агрессивный кэш CSS/JS

Приватное окно. Или Network → Disable cache → Ctrl+F5.

19.4. iOS Safari: background-image не отрисовывается

Только <img> с position:fixed.

19.5. iOS Safari: mask-composite + blur + scale крашит рендер

Маска на картинке, не на обёртке. Без mask-composite на iOS.

19.6. Незакрытая } в CSS ломает следующие правила

После вставки блока — навести на {, убедиться в парной }.

19.7. iOS Safari: анимация position:fixed за границей экрана

Сдвиг уменьшен до 50px + opacity + visibility с задержкой.

19.8. iOS Safari: событие scroll во время инерционной прокрутки

Использовать touchend вместо scroll.

19.9. Скрипт выполняется раньше HTML

Обернуть в DOMContentLoaded.

19.10. JS: рекурсия в getActiveDesign

Урок 9 октября 2026. При глобальной замене getDesignFor(activeDesignScreen) → getActiveDesign() через Replace All заменилась строка внутри самой функции getActiveDesign. Получилась рекурсия → Maximum call stack size exceeded.
Правило для профилактики: при Replace All — сначала подумать, что внутри заменяемого места может быть то же самое. После замены — проверить, что функция не зовёт сама себя.
