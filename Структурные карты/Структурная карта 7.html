2 · Кто пользователь

Личный проект для себя. Не для клиента, не для портфолио.

Главное

  • Не программист. Работает в VS Code и GitHub Desktop, код копирует.
  • Windows 11. Техника: iPhone 13, iPhone 16 Pro Max, iPad Air 11 (M2), ПК.
  • Внимательна к деталям. Заметит нечитаемый текст, кривую линию, лишние полосы, нестыковки превью и сайта.
  • Устаёт от длинных инструкций. Один шаг за раз: сделала → сохранила → обновила → показала → следующий.
  • Лучше понимает визуально. Скриншоты работают. Скрины со стрелочками работают лучше всего.
  • Есть вкус. Отклоняет то, что не подходит, объясняет почему.
  • Честная. Скажет прямо: «не нравится», «убери», «ты торопишься», «ты меня запутал», «не помню».
  • Разбирается в DevTools. Спокойно открывает Console, вводит команды, присылает результат. Открывает Network, ставит Disable cache.

3 · Как работать с ИИ

Главные правила (не нарушать)

Перед отправкой кода — свериться с этой картой. Не по памяти. Длинный диалог → доверять карте и скринам, а не «кажется, я помню».
Сначала решение — потом код. Пока пользователь не сказал «ок, давай код» — обсуждаем словами. Никакого кода заранее.
Один шаг за раз. Сделала → сохранила → обновила → показала → следующий. Не давать десять правок в одном сообщении.
Код — целым блоком. Не «замени строчку». Либо «найди этот текст → замени на этот текст», либо «удали эти строки», либо «поставь курсор в конце строки X, нажми Enter, вставь это».
Не повторять код, если он уже был дан. Если пользователь его получил — не дублировать, только напомнить, что он выше в переписке.

Как формулировать правки (важно!)

Формат 1 — замена по тексту. «Найди в файле этот код: [блок]. Замени его целиком на: [блок]».
Формат 2 — замена по номерам строк (когда видно на скрине). «Замени строки 296–322 на этот блок». Но номера видны только на скрине с номерами. Если номера могут «поехать» — использовать Формат 1.
Формат 3 — вставка. «Поставь курсор в конце строки X. Нажми Enter. На новой строке вставь этот блок».
Формат 4 — удаление. «Удали эту строку целиком». «Удали эти строки: от … до …».
Если пользователь не находит то, что ИИ просит — не угадывать. Попросить скрин нужного места с номерами строк. По скрину дать точную инструкцию. Не продолжать угадывать вслепую.
Если пользователь говорит «этого нет» — немедленно остановиться и попросить скрин. Не придумывать ещё один вариант правки «на всякий случай».
Не давать код сразу, если не согласовано решение. Пользователь просила: «сначала решение — потом код». Если ИИ начинает сразу писать блок — это раздражает.

Commit + Push — обязательно перед проверкой на устройстве

У пользователя нет прямого доступа к файлам на iPhone/iPad. Проверить можно только через GitHub Pages — для этого нужен Commit + Push.
Если пользователь должна посмотреть на iPhone/iPad — в инструкции первым делом: «сохрани, обнови на ПК; если ок — Commit + Push; подожди 1–2 минуты; открой на устройстве».

Как пользователь проверяет

DevTools (F12) в браузере — рабочий инструмент. Умеет:
  • Открыть Console, ввести команду, прислать результат.
  • Открыть Network, поставить Disable cache.
  • Открыть Elements, выделить элемент, показать Styles.
Практика: если правило есть в файле, но не применяется — проверить через Console.

Честность про память

Если диалог длинный и ИИ начинает путаться — сказать прямо: «Я начинаю терять нить». Не делать вид, что помню.

Что пользователь уже знает

VS Code GitHub Desktop Live Server Commit / Push GitHub Pages HTML / CSS Тег, класс DevTools (F12) Console, Network Кэш браузера Ctrl+Z откат

Рекомендации ИИ для следующей сессии

  1. Скрины со стрелками — лучший язык. Не понимает с первого раза — сразу просить скрин.
  2. «Не то» без объяснений — нормально. Спрашивать: «что именно не то — цвет, яркость, читаемость, размер, расположение?»
  3. При застревании — просить файлы. «Пришли index.html, card.css, style.css» работает как reset.
  4. Проверять закрытие скобок в CSS. Уже трижды незакрытая } ломала следующие правила.
  5. DevTools Console — рабочий инструмент. Проверять гипотезы через getComputedStyle, document.querySelector — быстро и без правок.
  6. Не забывать про !important. Когда старое правило мешает и не находится — добавлять в конец файла.
  7. Проверять иерархию цветов. Тёмная тема: плашки светлее фона, badge — акцент.
  8. Не бояться переспрашивать. «Покажи скрином» — быстрее, чем тыкать вслепую.
  9. У пользователя есть вкус. Когда говорит «не читается» или «не вписывается» — это точное попадание.
  10. Не давать код без согласования решения. Сначала обсуждаем словами, потом — код.

Контраст плашек — правила

Плашки (теги, кнопки порций, «Сковорода», «Моя заметка», кнопки внизу). Переменные:
  • --plate-bg — фон плашки
  • --plate-text — цвет текста
Логика по оттенкам:
  • Нежная, Светлая, Яркая → --plate-text: var(--c4).
  • Насыщенная, Глубокая → --plate-text: #fff, --plate-bg: mix(c3 15%, c2 85%).
Плашки в содержании на тёмной теме — наведение. новое в v7
При наведении плашка светлеет: фон var(--c2), текст var(--c4). Как в светлой теме. Раньше в тёмной плашка только двигалась, но не перекрашивалась.
Правило: без неона. Цвета приглушённые, спокойные.

5.6. Фоны ✅ финализированы в v5

В папке images/ — 19 картинок (01–05, 07–20; файл 06 отсутствует).

Как работает.
  1. Двухслойный фон: bg-blur (размытая) + bg-sharp (чёткая).
  2. Размытие — через <img>, не через background-image (Safari на iOS не рисует background-image на body).
  3. Картинка вписана целиком (object-fit:contain).
  4. Мягкие растворы краёв — mask-image: radial-gradient(...).
  5. Позиция и зум — переменные --tx / --ty / --tz.
  6. Редактор позиции — модалка, открывается из панели 🎨 (📐 Позиция).

Три слота — по устройству

Отдельная настройка для каждого:
  • Определение — нет тача → pc; тач + ширина < 600px → iphone; тач + ширина ≥ 600px → ipad.
  • Хранилище: bgSettings[bgId] = { iphone:{x,y,z}, ipad:{x,y,z}, pc:{x,y,z} }.

5.7. Фон сайта темнее карточки ✅ в v6

Карточка: --c1 (светлый).
Фон сайта: color-mix(in srgb, var(--c1) 65%, var(--c2) 35%) — чуть темнее. Карточки «выступают» из фона.

18 · Известные баги браузеров

18.1. iOS Safari: position:fixed + z-index:-1

Симптом. Фон с position:fixed; z-index:-1 на iPhone/iPad: при скролле фон уезжает.
Решение.
  1. Фон — position:fixed; z-index:0.
  2. Контент в обёртке <div class="app"> с z-index:1.
  3. На .bg-layer — translateZ(0) и will-change:transform.

18.2. iOS Safari: полоса внизу экрана

Симптом. Внизу полоса между картинкой и панелью Safari. Решение — оставили как есть.

18.3. iOS/iPadOS Safari: агрессивный кэш CSS/JS

Решение: приватное окно. Или DevTools → Network → Disable cache → Ctrl+F5.

18.4. iOS Safari: background-image не отрисовывается

Симптом. Фон через background-image на <body> или <html> не рисуется.
Решение: только <img> с position:fixed.

18.5. iOS Safari: mask-composite + blur + scale крашит рендер

Симптом. Комбинация filter:blur(40px) + mask-composite: intersect + transform:scale — Safari крашит страницу.
Решение:
  • Маска на картинке, не на обёртке.
  • Один радиальный градиент вместо двух линейных.
  • Никаких mask-composite на iOS.

18.6. Незакрытая } в CSS ломает следующие правила

Симптом. Правило есть, но не применяется. Или следующее правило «прилипает» внутрь предыдущего. Уже трижды случалось.
Правило для профилактики:
  • После вставки блока selector{...} — проверять, что } на месте.
  • В VS Code навести курсор на { — подсветится парная }.

18.7. iOS Safari: анимация position:fixed за границей экрана новое в v7

Симптом. Плавающие кнопки при исчезновении (уезжают на 300px вниз) — анимировались мгновенно. Появление (выезжают внутрь) — плавно. Safari «оптимизирует» анимации того, что вне экрана.
Решение — Вариант В:
  • Сдвиг уменьшен с 300px до 50px — кнопки остаются в зоне видимости.
  • Одновременно — opacity: 0.
  • Анимация 400ms — плавно и туда, и обратно.
  • Плюс visibility:hidden с задержкой .4s — чтобы не «ловили» тапы.

18.8. iOS Safari: событие scroll не срабатывает во время инерционной прокрутки новое в v7

Симптом. Пока палец двигает страницу — событие scroll молчит. Кнопки не прячутся.
Решение. Использовать touchend (отрыв пальца) вместо scroll для запуска таймера скрытия. Плюс touches.length === 0 — считать, что палец убран полностью.

18.9. Скрипт выполняется раньше HTML новое в v7

Симптом. Скрипт в <head> или до элементов DOM — не находит .fab-stack, молча выходит.
Решение. Обернуть в document.addEventListener('DOMContentLoaded', function(){...}).

20 · Технический долг

🟡 Средний приоритет

1. Объединить дублирующий CSS

Проблема. Стили .design-panel и .bg-editor частично дублируются.
Решение. Вынести общие части в .modal, .modal-box и т.д.

2. Унифицировать имена data-атрибутов

Проблема. Смешаны: data-s, data-p, data-shade, data-sh, data-th, data-bg, data-style, data-palette, data-shadow, data-fab-shadow, data-theme. Разнобой.
Решение. Привести к единому виду. Одновременно править HTML и JS.

3. Вынести JS в отдельные файлы

Проблема. Весь JavaScript — внутри <script> в index.html. Сейчас ~1300 строк. При добавлении поиска, фильтров, плана, кладовой станет >2500 строк.
Решение. Разбить на файлы в app/js/:
  • bg.js — фон, редактор, слоты.
  • design-panel.js — панель 🎨, стиль, палитра, тени, тема, фон.
  • fab.js — плавающие кнопки + автоскрытие.
  • main.js — загрузчик, содержание, утилиты.
Подключать через <script defer src="...">.

4. Убрать «хвосты» старой панели «Тема» новое в v7

Проблема. После переноса тумблера в шапку панели старые стили .dp-themes остались в CSS, а id dpThemes — в JS. Они не используются, но мусорят.
Решение. Удалить после того, как убедимся, что всё работает.

🟢 Низкий приоритет (чистка)

5. Удалить старые HTML-карты

Проблема. Лежат Структурная карта 5.html и 6.html. Обе устарели.
Решение. Оставить только 7.html. Удалить 5 и 6.

6. Удалить старый ключ bgPositions

Проблема. Старый формат заменён на bgSettings. Старый ключ остался.
Решение. Добавить в JS: localStorage.removeItem('bgPositions').

7. Проверять закрытие скобок в CSS

Привычка. После вставки блока — навести на { и убедиться в парной }.

⚪ Отложено

8. Минификация CSS и JS

Не делаем. Для личного проекта не нужно.

9. Единая система данных (рецепты в объектах JS)

Проблема. Рецепты захардкожены в index.html. Для 9 карточек ок. Для 150+ — невозможно.
Решение. Отдельный большой этап (шаг 23).
